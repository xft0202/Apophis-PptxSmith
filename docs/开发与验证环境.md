# 本机开发与验证环境

记录日期：2026-09-28。项目仍是立项前调研，当前范围见 [当前需求与工作约定](当前需求与工作约定.md)。

## 工作约定

所有者后续只在当前本机开发、测试与开展获授权的验证，不再以 Windows 开发机、Docker Desktop、x86 PowerShell、WPS COM、第二台机器或远程 Office 环境为前提。

这是工作环境约定，**不等于产品必须采用 Linux Docker 部署，也不产生 PowerPoint/WPS 兼容承诺**。调查和测试应围绕实际研究问题选择，不因已有工具就提前锁定架构。

## 研究验证如何安排

- 先说明要回答的问题、输入材料和判断方法，再选择本机工具；不默认恢复旧 benchmark 或旧工程任务。
- 可按需要安排文件结构、数据一致性、字体度量、解析或预览等本机验证，但这些是可用的研究手段，不是已冻结的产品质量门。
- 对外部模型、账号、付费接口、额外软件安装和新增服务，先明确授权与影响范围。
- 记录输入、工具版本、执行动作、结果与未覆盖范围；失败如实记载，不靠截图或文字承诺补齐证据。
- 本轮未授权新的引擎比较、生产脚手架或产品开发，不能因文档清理自行执行。

## 历史 Windows 证据

2026-09-24 至 2026-09-26 的实验曾使用 Windows、WPS 演示 11.8.2.8411、32 位 COM 与 Docker Desktop。它们证明的只是当时样本和环境中的结果，不代表当前机器，也不是后续开发测试的安装清单。

- 历史 WPS 探针及其结果保留在 `research/experiments/`，用于阅读和追溯。
- 带 Windows 盘符、COM 或专有字体路径的旧命令不是本机执行说明；不要求为了复跑它们恢复 Windows。
- 若以后确有研究问题需要其中某项能力，应重新设计本机可执行的验证；不存在等价手段时明确记录证据缺口，不改写旧结果。

历史资料索引见 [研究资料](../research/README.md)。

## 证据表达

「已安装」「可调用」「本机实测通过」「历史环境通过」「未验证」是不同状态。结构检查只证明结构检查项，LibreOffice 预览只证明该工具和版本的结果；不得自动推导其他软件兼容性。是否需要某种兼容性，应由需求分析决定，而不是由测试环境倒推用户承诺。
