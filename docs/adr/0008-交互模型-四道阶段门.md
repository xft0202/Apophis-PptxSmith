# 交互模型：对话式四道阶段门（澄清门→大纲门→代表页门→交付门），无画布

Status: accepted (2026-09-24，所有者有条件确认，HITL 尽调通过）

产品的生成交互为对话式四道阶段门：①澄清门（最多 3 个影响结构的问题，可跳过，默认值可见）→ ②大纲门（结构化大纲面板：增删/调序/锁定，是面板不是画布）→ ③代表页门（2–3 张不同角色样页真实编译后确认方向，允许老用户跳过）→ ④交付门（自动交付闸门 + 审计报告，人工不可降级绕过）。修改路径 = 对话指令（定位到页/对象）+ 大纲面板直改 + Gamma 式预览回滚。**不做自由画布编辑器。**

## 尽调依据（2026-09-24 第五轮）

- "澄清→大纲确认→生成"是 Gemini/Gamma/Plus AI/SANDUN 四方共识（官方文档），非独家设计；
- HITL 文献一致警告：**门只应设在错误代价高或不可逆处**，过度设卡导致确认疲劳与橡皮图章。据此校准：澄清门守"受众/场景错则全稿报废"的高爆炸半径错误；大纲门守全量重生成成本；代表页门守方向性视觉错误（全量生成成本高但可逆，故必须**可跳过**并展示成本预估）；交付门是自动质量门，不占用用户摩擦预算；
- 反例路线存在：Manus/Genspark 主打全自动出稿。取舍说明：滩头场景（公司内部正式汇报）中"错误当众出丑"的代价高于等待几十秒，故保门；同时记录跳过率遥测，若用户普遍跳过代表页门则降级为可选开关。

## Considered Options

- 全自动无门（Manus 式）：被否，理由同上；但保留"信任老用户可连续跳过"的逃生阀。
- 画布编辑器（SANDUN/Kimi 式）：被否。投入以年计；目标人群交付后本就在 PowerPoint 中继续编辑。

## Consequences

- 代表页门必须在 UI 显示成本预估（页数、预计耗时、模型档位），否则门没有信息价值；
- 跳过遥测（匿名、本地统计）进入 v0.2 评估项；
- 门状态是项目数据模型的一部分：每个阶段门有确认人、时间戳、跳过标记，进入审计记录。
