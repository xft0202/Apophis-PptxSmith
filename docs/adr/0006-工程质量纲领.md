# 工程质量纲领：长期主义、企业级水准、禁止临时方案进主线

Status: accepted (2026-09-24，所有者明示）

项目按长期维护的开源企业级产品标准建设，不是一次性原型。具体化为以下不可妥协项：

- **主分支纪律**：进入主线的代码必须带测试与文档；标注 `TODO`/`FIXME` 的临时实现不得跨过版本发布。研究性 spike 只允许活在实验分支或独立目录，且须自我标注"可丢弃"。
- **证据纪律**：任何文档（含 README、报告、提示词注释）中的外部事实必须带证据级别标注（官方声称/第三方实测/本项目实测），禁止把宣传写成事实。
- **验收纪律**：每份交付的 PPTX 过交付闸门（容器/包关系/对象清单/溢出/可编辑等级）；中文验收以真实 PowerPoint/WPS 打开为准，禁止以浏览器或 LibreOffice 渲染替代。
- **依赖纪律**：新依赖必须过许可证（MIT/Apache/BSD）与维护状态审查，记录到依赖清单。
- **设计纪律**：先定接口与语义模型，再实现；禁止边写边想出现在主线。设计分歧走 docs/adr/ 记录。

## Consequences

- v0.1 的范围宁可砍功能，不降上述标准。
- 迭代速度让位于可维护性：每个里程碑结束时的代码必须处于"新人可读、可接手"状态。
