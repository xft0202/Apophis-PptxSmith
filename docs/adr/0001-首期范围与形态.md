# 首期范围与形态：新建优先，旧稿延后，不自建编辑器，长期开源

Status: accepted (2026-09-24，与项目所有者第一轮追问确认)

项目将长期开源托管于 GitHub。首期只做**新稿编译**（材料→可编辑 PPTX）；**受控补丁**（旧稿局部修改）降为背景目标，不在首期承诺范围内。首期不自建在线编辑器，交付后用户在自己的 PowerPoint/WPS 中继续编辑——这本来就是目标人群（公司内部汇报场景）的真实习惯。滩头场景定为公司内部工作汇报/培训/展示（听众：领导、同事），原 `input/例子.pptx` 样本作废（所有者已删除）。

## Considered Options

- 新建与旧稿并行：被否。旧稿补丁验收成本最高且 Kimi K3 正在追赶，但首期资源无法支撑双线；旧稿作为差异化候选保留，待新建闭环验证后再投入。
- 自建在线编辑器（仿 Kimi/Gamma）：被否。投入以年计，且不构成首期价值验证的必要条件。
- 商业 SaaS：被否。项目定位为长期开源。

## Consequences

- 02 可行性报告中的 Java 21 编排假设、12 周双人排期、旧稿补丁双原型计划全部需要按开源单人/小团队现实重估（见第二轮追问）。
- 依赖许可政策随之收紧：只能引入与开源分发兼容的许可（MIT/Apache-2.0/BSD）；PPTist（AGPL）、Dashi 导出包（专有）、Anthropic pptx skill（Proprietary）仅作思想参考。
- 验收以真实 PowerPoint/WPS 打开为准的纪律不变。
