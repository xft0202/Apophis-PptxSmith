# 本机开发测试与历史验收环境分离

Status: accepted for working environment (2026-09-28，所有者要求后续仅在当前本机开发测试；原 2026-09-25 Windows 环境方案转为历史记录）

所有者已不再使用 Windows 开发；本轮观察到当前本机为 Linux x86_64。后续开发、测试与获授权实验只在本机进行，不把历史 Windows/WPS/COM 环境当成现有设施。项目处于立项前调研，遵循「博采众长，取其精华，去其糟粕」，以 SANDUN 为明确参考但不限定唯一答案；这些与本机工作方式共同构成当前约定，见 [当前需求与工作约定](../当前需求与工作约定.md)。

## 当前决定

1. **仅在当前本机工作**：代码检查、单元测试、文件结构检查及需要隔离的容器实验均在本机执行；不要求另建 Windows 机器、VM 或远程验收链。
2. **不依赖 Windows 工具链**：Windows 盘符、Docker Desktop、x86 PowerShell、WPS COM、`wpp.exe` 不再是当前开发测试的前提。它们只存在于历史实验或历史环境记录中。
3. **环境可用性与测试结果分开**：Docker/Compose 和 LibreOffice 命令可调用，只证明工具可用；没有执行的验证不得标为通过，缺失的依赖也不得凭旧文档假定存在。
4. **不推导产品承诺**：本机开发不自动决定产品部署方式；PowerPoint/WPS 支持、双宿主验收、A 级语义及中文零溢出均属待确认建议，不是本次工作约定的附带要求。
5. **保留证据边界**：若未来选择某办公软件作为验收目标，应另行明确版本、样本和动作；本机结构检查或预览只能报告实际覆盖范围，不冒称其他软件验证通过。
6. **本次不授权新实现或比较**：整理文档不等于批准生产脚手架、引擎 benchmark、软件采购或新增基础设施。

## 历史方案与不再适用的部分

2026-09-25 的方案记录了一台 Windows 上的 WPS 演示 11.8.2.8411、32 位 COM、Docker Desktop 29.7.2 / Compose 5.4.0，并把 Microsoft PowerPoint 标为未验证。该方案反映的是当时环境，**不反映当前机器，也不是当前工作要求**。

原文中「Linux Docker 是唯一产品部署形态」「WPS 是当前唯一验收宿主」「PowerPoint 缺位用保守系数补强」不再由本 ADR 作为当前产品约束背书。相关产品和质量建议需要重新确认；旧版本及实测记录仍可追溯。

历史样本的 WPS 打开、编辑、保存、重开证据不删除、不改写为 Linux 测试，也不扩张到新的样本、版本或产品能力。详细环境与证据状态见 [开发与验证环境](../开发与验证环境.md)。

## Consequences

- 调研入口、研究结论和实验说明应指向当前约定，不能继续要求恢复 Windows 环境；旧工程任务地图已清理，不作为研究前置条件。
- 依赖 Windows/Office 的作者路线只能作为历史研究或未来可重新讨论的方案，不进入当前本机执行计划。
- 现有 Windows 探针保留为历史工具；迁移开发环境不要求把它们重写成 Linux 上的等价验证。
- 本机环境变化时追加日期与测量记录，不覆盖历史实验事实。
