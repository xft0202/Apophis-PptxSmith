# 调研现状与下一步

检查日期：**2026-10-01**。定位：**立项前调研**，不是立项完成后的工程启动计划。统一结论见[四大块立项前研究统一结论](../research/2026-10-01_四大块立项前研究统一结论.md)；当前方向以 [当前需求与工作约定](当前需求与工作约定.md) 为准。

## 本轮目的地（2026-09-28 已确认）

所有者选择：**立项判断与推荐方案**。本轮需要把竞品、需求、可行性和技术架构路线连接起来，形成有证据的方向建议、备选方案、风险与未决问题清单，供所有者决定是否及如何立项。

已确认的研究起点与参考范围：

- **使用对象与研究起点**：所有者已纠正人群限定，任何有演示文稿相关需求的人都可使用，不按职业、身份或人群排除使用者。此前将「广大普通上班族」固化为产品边界的表述撤销；调研按任务、输入、目的和使用过程推进，样本人群只说明证据范围。
- **SANDUN 参考范围**：交互与生成流程、页面设计与视觉表现、内容生成与材料处理、输出产物与后续修改，四个维度均纳入研究。这不意味着采用其全部功能或实现。

这不是只做资料汇编，也不代表现在立项、冻结功能或锁定技术栈。研究安排按问题依赖逐轮收敛，暂不凭空填写工期；发现证据不足时明确给出条件性结论或暂缓建议。

研究目的地和 SANDUN 四维参考范围保持不变。使用对象按所有者最新纠正不设人群边界；五轮计划按演示文稿任务推进，不需要先圈定一种人群。正式入口为 [立项前调研：AI 演示文稿产品的立项判断与推荐方案](https://github.com/xft0202/Apophis-PptxSmith/issues/1)。

本轮[研究地图](https://github.com/xft0202/Apophis-PptxSmith/issues/1)已于2026-10-01结案：技术研究和评价原则已收尾，独立探针议题按既有纠正退出本轮范围。所有者确认四大块研究收口，不立项；未来验证、技术终决或开发须另定范围与授权，不继承为自动执行任务。

首项「演示文稿创作与使用任务有哪些可靠的痛点证据？」已完成现阶段公开一手资料调查与父代理复核，结论见 [研究结案记录](https://github.com/xft0202/Apophis-PptxSmith/issues/2#issuecomment-5868824568)，本机资产见 [任务与痛点证据报告](../research/2026-09-28_演示文稿任务与痛点证据调查.md)。它提供有边界的候选任务，不证明总体高频、市场需求或立项通过。

既有文献与真实样本保留，不以样本身份定义使用资格。原独立分支 research/office-worker-ppt-evidence 仅用于原稿和过程追溯，不代表当前人群定位。任务报告已完成现阶段事实调查与复核。随后按所有者纠正，直接推进实质竞品分析，不再把任务组合确认或“探针设计”作为独立主线；材料选择和比较方法由代理承担。现已交付[综合竞品分析](../research/2026-09-28_演示文稿产品与开源Skills竞品分析.md)与[开源／Skills 子报告](../research/2026-09-28_开源演示项目与Skills竞品调查.md)，覆盖四项成品平台、六项开源／skill 与 Slidev 补充对照，保留实际效果和成本未验证的边界。

- **技术选型**：[有界技术路径一手资料调查](../research/2026-10-01_技术路径一手资料调查.md)已完成父代理复核。比较网页表达、文件对象、作者环境辅助、复用／二开与可替换组件组合；列清表示、状态、模型接入、失败恢复、平台和许可边界。没有选定技术栈、产品路线或库；没有运行SDK或恢复旧排序。

## 三、接下来研究什么

以下是推进建议，不是已冻结的功能或技术要求。

### 1. 首轮：演示文稿任务与痛点

优先调查演示文稿在什么任务中被创建、改编、讲解和交付，以及输入材料、沟通目的、困难和证据强弱。候选可以横跨不同人群；具体案例用于观察与比较，不定义哪些人有资格使用。用户可以按自己的需求自由组合和发挥，研究样例不构成固定流程、产品允许清单或能力上限。不得把已有文献的样本当成产品的人群边界，也不把场景例子写成已确认需求。

利用已有资料并补关键缺口，区分直接观察、第三方声明和推断；不把产品营销话术等同于用户需求证据。资料入口见 [研究索引](../research/README.md)，无需重新做一轮全仓库清点。

**产出**：候选任务、痛点与证据矩阵，以及用于观察差异的开放式研究探针。该产出已完成现阶段公开资料调查，详见 [研究结案记录](https://github.com/xft0202/Apophis-PptxSmith/issues/2#issuecomment-5868824568) 与 [任务与痛点证据报告](../research/2026-09-28_演示文稿任务与痛点证据调查.md)。探针由代理负责选择、组合、补充和调整；不等于所有者已确认的场景、产品需求或用户必须遵守的组合。

### 2. 竞品分析：以 SANDUN 为重要参考，横向取长补短

直接比较 SANDUN、其他成熟平台、活跃开源项目和 PPT／Slides skills 的交互、视觉机制、材料处理及输出修改边界，说明优势、限制与借鉴理由。比较材料由代理负责，不要求所有者先选任务组合，也不以方法设计替代实质分析。

逐项记录：实际观察、优点、缺点、适用条件、可吸收部分和不采用理由；不能只列功能表，也不能把某产品的全部设计当成基线。已有其他产品资料可用于筛选后续深入对象，具体功能和价格在需要比较时重新核实。

**产出**：已形成[有证据的横向比较](../research/2026-09-28_演示文稿产品与开源Skills竞品分析.md)，包括「取什么、不照搬什么、为什么」、路线备选与五项关键未知。当前是文档／源码调查、历史样本与一次有界运行验证的整合，不是统一成品效果 benchmark。这些证据已连接到候选需求与五条路线；后续只补能改变具体判断的缺口，不重开竞品综述、不再继续模型实验。

### 3. 需求分析：从场景与痛点形成候选需求

梳理潜在使用者、真实任务、现有工作方式、主要困难和期望结果。区分用户明确要求、从观察得到的假设、代理提出的建议与尚未确认的事项。

不要直接把旧报告中的多账号、BYOK、四道门、可编辑等级或特定办公软件验收搬回需求清单。每项候选需求都应有来源、收益、代价和优先级理由。

**产出**：已形成[四项价值假设和九项候选需求](../research/2026-09-28_候选需求与价值假设.md)，逐项注明证据、收益、反例与代价；研究优先顺序不是首期范围，也不构成用户必须遵循的任务组合。

### 4. 可行性分析

判断候选需求的用户价值、完整工作链、人工与维护负担、外部依赖、失败恢复、成本和反转条件。不要用单个工具能生成文件代替完整可行性，也不要用几次实验失败推导整个方向不可行。

**产出**：已区分问题线索、单项机制、端到端效果、运行维护与经济采用五层证据，记录成本构成和可能反转判断的风险，见[清理后的可行性建议](../research/2026-09-28_可行性与立项路径建议.md)。没有实际生成或效果测试，不报虚构的费用、成功率或工期。

### 5. 技术选型

**产出**：已从需求和可行性结论重新完成[技术路径一手资料调查](../research/2026-10-01_技术路径一手资料调查.md)，区分产品架构路线、组件能力与许可边界。研究已完成但未选型；版本/API事实和残余风险见报告，不据此批准实施。

### 6. 汇总立项判断材料

已形成[四大块立项前研究统一结论](../research/2026-10-01_四大块立项前研究统一结论.md)，连接用户任务、竞品机制、候选需求、端到端可行性与技术路线边界，给出条件性推荐、替代路线、完整任务证据门槛及停止信号。所有者已于2026-10-01确认共享理解并收口研究，不是立项批准或路线授权。

[立项取舍与验证授权边界](../research/2026-09-28_立项取舍与验证授权边界.md)保留阶段边界：不正式立项、不定技术栈、不启动产品开发。Presenton 运行验证已经封口，不再重试模型、修复中转兼容性或扩大模型比较。

研究阶段四块材料现已齐备；下一步优先补证建议是经单独授权后进行有界完整任务比较，采用与经济性仍如实保留未验证。是否执行及是否立项由所有者决定。

## 四、清理、建图与研究推进边界

- 保留可追溯的采集、实验和技术来源资料；历史 Windows 结果没有改写为 Linux 实测。
- 删除失效的旧 v2 定案报告、旧工程地图/任务、产品/架构硬约束与路线授权门，减少相互冲突的入口。
- 当前约定为立项前调研、博采众长、SANDUN 四维参考与本机工作；使用对象不设人群边界，按任务组织研究，目的地为立项判断与推荐方案。
- 完成了从任务痛点、竞品、候选需求和产品工作链可行性，到技术路径边界的研究；完成不等于选型、立项或开发授权。
- 研究主判断轴为减少全流程返工；用途决定交付底线；正式开发前需要有界完整任务证据。
- 本轮没有运行模型、候选产品或SDK，没有采购、安装办公软件或启动实现；Presenton验证保持封口，未提交或推送Git。
