# 产物技术需求（技术选型的判据来源）

- 制定日期：2026-09-26
- **性质：这是技术选型的起点，不是过程产物。**
- 编制原则：**从产品出发反推技术需求**，而不是从候选出发找理由。
  此前的方法错误是「哪个库活跃 → 哪个能过门 → 二选一」，
  正确顺序是「要做成什么 → 需要什么能力 → 哪些技术能满足 → 谁最强」。

---

## 0. 为什么要有这份文档

所有者指出：当前根本不是技术选型，一直在弯弯绕绕。经核查，问题在于
**从来没有把产品承诺翻译成可实测的技术需求**——所以候选比较没有判据，
只能退化成「活跃度打钩」。

**本文件的作用**：把 VISION.md 与 CONTEXT.md 里的产品承诺，
逐条翻译成**可实测的技术能力要求**，作为所有候选比较的唯一判据。

**每一条都必须是**：可观测、可在 WPS 上验、有明确的通过/失败判据。
不允许出现「支持良好」「性能优秀」这类无法验证的表述。

---

## 1. 产物规格（要先做出来的东西长什么样）

技术选型必须能造出**这样一份 PPTX**：

| 项 | 要求 |
| --- | --- |
| 规模 | 中文商务汇报，**10–20 页**（不是 3 页验证片） |
| 页面角色 | 封面 / 目录 / 章节页 / 内容页 / 结束页（至少 4 种角色） |
| 图表 | **原生图表**，携带**嵌入工作簿**；改数值后图表更新 |
| 表格 | **原生表格**，可增行、可改格 |
| 插图 | 图像模型生成的**插图素材**，作为**原生图片对象**（可替换/裁剪） |
| 文本 | 全部为**真文本**，可选中、可改字 |
| 中文 | 长段中文、中英混排、数字与标点；**零溢出、不乱码** |
| 备注 | 演讲者备注页 |
| 母版/版式 | 主题、母版、版式可用（不是只有 1 个 theme、0 个 layout） |
| 字体 | 不出现目标机器不存在的字体名（**禁止 `system-ui` 这类 CSS 字体族泄漏**） |
| 目标软件 | 在 **WPS 11.8.2.8411** 打开无修复提示、可编辑、可保存、重开一致 |

## 2. 技术能力需求清单（按产品承诺反推）

### 2.1 来自铁三角之一：**A 级原生语义**

> 承诺：「交出去的每一页，在 PowerPoint/WPS 里能继续改——图表改数值、表格加行、
> 文字改段落，都是原生对象，不用重画。」

| 编号 | 能力要求 | 可观测判据 |
| --- | --- | --- |
| **A1** | 生成**原生图表部件** `ppt/charts/chart*.xml` | 解包存在该部件，且 WPS 中双击图表有数据表 |
| **A2** | 图表携带**嵌入工作簿** `ppt/embeddings/*.xlsx` | 解包存在；`<c:externalData>` 引用成立 |
| **A3** | 改图表数值时**同步图表缓存与嵌入工作簿** | 改 B3 → 另存 → 重开后缓存与工作簿一致（Spike C1 已验路线） |
| **A4** | 生成**原生表格** `<a:tbl>` | WPS 中可增行、可改格并持久 |
| **A5** | 文本为**真文本 run** `<a:t>` | 可选中改字；**不是**形状拼的、不是图片 |
| **A6** | 插图作为**原生 `<p:pic>`** | 可替换图片、可裁剪，页面其余对象不受影响 |
| **A7** | **备注页** `ppt/notesSlides/*` | 存在且内容正确 |
| **A8** | **主题/母版/版式**齐备 | `ppt/theme/`、`slideMasters/`、多个 `slideLayouts/` 存在 |
| **A9** | **零图片化**：禁止把承诺对象静默转成图片/形状 | `pictures` 计数仅等于插图数量；无「图表形状拼图」 |

### 2.2 来自铁三角之二：**中文零溢出**

> 承诺：「中文排版出厂即合格——不溢出、不乱码、换机不走样。」

| 编号 | 能力要求 | 可观测判据 |
| --- | --- | --- |
| **B1** | 精确控制字体、字号、**行距**、段落间距 | 能写出与量字引擎预测一致的行高 |
| **B2** | 能设置**文本框尺寸与自动换行**，实现「量字烘焙」 | 预测 N 行 → 实际渲染 N 行且不溢出 |
| **B3** | 能控制**中西文混排**的字体回退 | 中英数字标点均正常，无缺字 |
| **B4** | **不引入**目标机器不存在的字体名 | 解包 `typeface` 统计中无 CSS 字体族名 |
| **B5** | 能嵌入字体或提供可审计的字体替换策略 | 产物自包含或明确降级路径 |

### 2.3 来自铁三角之三：**事实保真与审计**

> 承诺：「你给的数据，一个字不改」+「每一份稿都带审计报告」。

| 编号 | 能力要求 | 可观测判据 |
| --- | --- | --- |
| **C1** | 能**读出**产物对象清单（对象种类、数量、位置） | 审计报告可列出逐对象条目 |
| **C2** | 能判定每个对象的**可编辑等级 A/B/C/D** | 自动分级，不靠人工目检 |
| **C3** | 能**校验 OOXML 包合法性** | 有 validator 可用（SDK 有 `OpenXmlValidator`） |
| **C4** | 能检查**关系与部件闭包**（无悬空引用） | 自研审计层可遍历 `.rels` |
| **C5** | 数字与来源**可追溯到材料 locator** | 对象级证据链 |

### 2.4 来自未来能力（影响当前地基，不必现在实现）

> 承诺：v1.0 的**受控补丁**（旧稿局部修改），首期不做但地基要留。

| 编号 | 能力要求 | 可观测判据 |
| --- | --- | --- |
| **D1** | 打开既有 PPTX 并**只重写授权部件** | 未授权部件字节不变 |
| **D2** | **未知部件 / 未知关系原样保留** | 夹具中的未知部件与关系在产物中原样存在 |
| **D3** | 能**逐部件**读写（OOXML 包级操作能力） | 可列举/替换单个部件 |

> **D2 有现成夹具**：`research/experiments/spike-D-fixtures/品牌参考.pptx`
> 含未知部件 `ppt/unknown/pptXsmithFixture.xml` + 未知关系，且生成器有三处路径一致性自检。
> **但从未用任何候选引擎跑过**。票 02 已注明「需回归夹具验证，不能由文档推导为保证」。

## 4. 判据的优先级（冲突时怎么取舍）

1. **A 级语义与中文零溢出优先于一切工程便利**——这是产品立身之本；
2. 二者冲突时（如某引擎能 A 级语义但中文控制弱），**以 A9「零图片化」为硬否决**；
3. 工程项（E1–E6）是**门槛**不是评分：不过门不进场，进场后不比工程分；
4. **D 项（未知部件保留）当前不作否决**——首期不做受控补丁；但**必须实测记录**，
   因为它决定未来能不能开这条路，且是「不能由文档推导」的那一项。

## 5. 由本清单导出的下一步（不在此文档内决策）

本清单一旦确认，技术选型才正式开始。顺序应为：

1. **用清单造参照物**：先选定一个引擎，**按第 1 节的产物规格造一份 10–20 页完整稿**，
   逐条实测第 2 节的能力项。**不做 3 页验证片**——验证片掩盖真实问题。
2. **同题换引擎再造一遍**：同一份材料、同一目标软件、同一判据。
3. **补全候选池**：特别是**商业 SDK 的能力基线**（如 Aspose.Slides）。
   其许可证不合规，但**能力上限是判断「自研要做到什么程度」的参照**——
   不知道天花板在哪，就不知道自己的方案够不够。
   → 其吸收分类为**必须隔离**（许可证），但**必须先评估能力**，
     因为「必须隔离」不等于「不必评估」。
4. **未知部件保留实测**：夹具已就绪，从未跑过。
5. **产出**：能力对比矩阵（逐条对第 2 节编号）+ 五分类落位 + 结论。

## 6. 本清单的边界

- 本清单**只定义「技术要满足什么」**，不指定任何技术、语言或库；
- 本清单**不构成对任何候选的推荐**；
- 本清单**替代**此前票 23 的判据部分——票 23 原列的 12 项能力要求过粗，
  且缺少本清单的 A2/A3/A7/A8/A9、B4、D2 等关键项；
- 所有实测必须标明**证据级别**（官方声称 / 第三方实测 / 本项目实测）。
