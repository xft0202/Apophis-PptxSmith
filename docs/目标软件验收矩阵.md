# 目标软件验收矩阵与宿主边界

*状态：已冻结（2026-09-25，所有者确认方案 A）*
*性质：环境事实登记 + 验收协议。**不涉及、不预判任何技术选型**；ADR-0003 仍为 `challenged`，ADR-0009 仍为 `proposed`。*

## 1. 必须区分的三个环境

本项目最容易混淆、且已经混淆过一次的三件事，在此一次性切开：

| 环境 | 是什么 | 谁使用 | 部署形态 | 是否接受用户安装 |
| --- | --- | --- | --- | --- |
| **生产运行环境** | 用户实际部署运行的 PptxSmith 服务 | 部署者（一人部署、多人使用） | **Linux 服务器 + Docker Compose**（ADR-0007，唯一受支持形态） | ✅ 只装 Docker + 配置自己的模型 key，**无其他新增安装项** |
| **验收宿主（Windows）** | 打开成品 PPTX、改图表/表格/文字、另存、重开复查的商业办公软件 | **仅维护者**（本项目开发/发布流程） | **本机 Windows（唯一一台）**，非部署目标、非产品节点 | ❌ 用户永远不需要安装它——它只出现在审计报告的「验证环境」字段里 |
| **容器化验证环境** | Spike D 的四套架构、数据库、对象存储、身份、provider gateway 夹具 | 维护者 | **Docker Desktop 内的 Linux 容器** | ❌ 不进生产镜像、不进 Compose 依赖、不进用户安装步骤 |

**核心纪律：验收宿主 ≠ 部署宿主。** Windows 上的 Office 软件是**维护者侧的质检工具与测量仪器**，不是产品运行依赖。任何把 Office SDK / COM 自动化 / Windows 服务写进生产依赖树、生产镜像或用户安装文档的做法，一律视为架构错误（由票 19 依赖边界检查强制）。

### 2.1 COM 自动化的 32 位前提（**硬性**）

WPS 的 COM 自动化服务器注册在 **32 位注册表视图（`HKLM\SOFTWARE\WOW6432Node\Classes`）**，而非 64 位节点。实测：

```text
PowerPoint.Application -> F:\WPS Office\...\office6\wpp.exe /Automation   [WoW6432Node]
KWPP.Application       -> F:\WPS Office\...\office6\wpp.exe /Automation   [WoW6432Node]
Word.Application       -> F:\WPS Office\...\office6\wps.exe /Automation   [WoW6432Node]
KWPS.Application       -> F:\WPS Office\...\office6\wps.exe /Automation   [WoW6432Node]
Excel.Application      -> F:\WPS Office\...\office6\et.exe  /Automation   [WoW6432Node]
KET.Application        -> F:\WPS Office\...\office6\et.exe  /Automation   [WoW6432Node]
```

**后果（不知道会浪费半天）**：

- 任何自动化操控 WPS 的验收脚本**必须以 x86 目标编译或通过 32 位宿主调用**；64 位进程 `CreateObject` 会找不到服务器或静默失败。
- `PowerPoint.Application` 与 `KWPP.Application` 在本机指向**同一个** `wpp.exe`，因此「用 PowerPoint ProgID」在这台机器上**不代表验到了 Microsoft PowerPoint**——脚本里必须显式断言宿主身份，不能靠 ProgID 判断。
- 手动验收不受此约束：人工在 WPS 里打开、编辑、另存、重开，即可作为验收证据，只是不可被贡献者脚本复跑（见第 5 节）。

## 3. 双目标验收矩阵

ADR-0007 定的「中文排版与编辑性必须以目标软件验收为准」在本项目现有的宿主条件下，按下表执行。

| 验收维度 | WPS 演示 11.8.2.8411 | Microsoft PowerPoint | 说明 |
| --- | --- | --- | --- |
| 打开无修复提示 | ✅ 可验（自动 + 人工） | ❌ **本机无正版 Office，不可验** | — |
| 图表数据可改且持久 | ✅ 可验，Spike A 已通过 | ❌ 不可验 | 改数值 → 另存 → 重开复查 |
| 表格可增行/改格并持久 | ✅ 可验 | ❌ 不可验 | — |
| 文字段落可改并持久 | ✅ 可验 | ❌ 不可验 | — |
| 嵌入工作簿同步（A 级语义核心） | ✅ 可验 | ❌ 不可验 | 图表缓存与 xlsx 部件必须一致 |
| 中文折行 / 行高 / 溢出 | ✅ 可验（校准基准即 WPS 实测） | ❌ 不可验；**改用保守系数外推** | 见第 4 节 |
| LibreOffice headless 独立渲染信号 | ✅ 容器内可跑（票 03 已冻结其角色） | — | 只作第二种信号，不代表目标软件 |

**矩阵结论**：v0.1 的目标软件验收以 **WPS 演示**为唯一实测目标；Microsoft PowerPoint 一侧**未验证**，并按第 4 节做保守补强。

## 4. PowerPoint 缺位的补强策略（方案 A）

不做静默降级。三条补强，全部零采购成本：

1. **量字采用保守系数**。Spike B 实测：纯字体度量在 WPS 下**系统性低估行高 5–8%**（末行溢出框外）；而 `cjk-pptx-engine` 按 PowerPoint 校准的系数（雅黑 1.34、宋体 1.16）比我们的 WPS 实测值（1.3198 / 1.1406）**更接近实测渲染高度**。因此：
   - 安全余量按**更保守的一侧**取，宁可留白多，也不让 PowerPoint 里溢出；
   - 校准表按「字体 × 目标软件」二维维护，PowerPoint 列填入外部校准值并标注证据级别为**第三方实测**，不得标为本项目实测；
   - **审计（而非预测）是最终防线**：溢出审计闸门必须在 WPS 中逐一复核，凡预测不确定即阻断交付。
2. **审计报告明示验证环境**。每份稿的审计报告写入：`验证环境：WPS 演示 11.8.2.8411；未验证：Microsoft PowerPoint`。让用户看见边界，而不是替他们猜。
3. **发布说明写明未验证范围**。v0.1 的 release notes 必须列出「本版在 Microsoft PowerPoint 上未做本项目实测验收」，措辞与 ADR-0006 的证据纪律一致。

**为什么接受这个降级**：滩头场景是公司内部工作汇报、培训、展示，听众为领导与同事；国内企业办公环境中 WPS 占比很高，WPS 是合理且必要的主验收目标。同时，`wpp.exe` 与 PowerPoint 的 COM 接口高度同源（连 `PowerPoint.Application` ProgID 都被它接管），因此 WPS 通过的对象语义与几何行为在 PowerPoint 中**大概率**成立——但这是**推断**，按证据分级只能标注为推断，**不得**写成已验证事实。

## 5. 验收执行协议

### 5.1 分层证据（呼应票 03 的结论）

交付门是**证据组合**，不是单项 PASS。各层只证明各自的范围：

| 层 | 工具 | 证明了什么 | 没证明什么 |
| --- | --- | --- | --- |
| 包 / Schema | OpenXmlValidator | OOXML 包与元素合法 | 视觉与交互等价 |
| 关系 / 部件闭包 | 自研审计层 | `[Content_Types].xml`、`.rels`、嵌入工作簿、外链、宏策略 | 渲染正确性 |
| 语义探针 | 自研审计层 | 对象清单、A/B/C/D 等级、零改写、来源 | 排版外观 |
| 字体 / 几何 | 统一 HarfBuzz-backed 量字 | 溢出、越界、重叠 | 目标软件实际观感 |
| 独立渲染 | LibreOffice headless（容器） | 第二种导入/渲染信号、批量截图 | PowerPoint/WPS 等价 |
| **目标软件** | **WPS 演示 11.8.2.8411** | **用户实际能否打开、编辑、保存、重开** | Microsoft PowerPoint 行为 |

### 5.2 WPS 自动化验收脚本规格

- **目标平台**：x86（见 2.1），或经 32 位宿主调用。
- **宿主断言**：启动后必须校验进程为 `wpp.exe` 且路径/版本匹配 `F:\WPS Office\11.8.2.8411\`，不匹配即失败并记录实际宿主。
- **探针序列**：打开（记录是否弹修复提示）→ 读对象类型清单 → 改图表数值 → 读回嵌入工作簿对比 → 表格增行/改格 → 文字改段落 → 另存新文件 → **重开** → 复查全部改动是否持久。
- **产物**：每样本一份 `wps-probe-<sample>.json`（宿主版本、时间戳、逐项 PASS/FAIL、失败对象清单、异常栈）+ 每页 PNG 截图。
- **沙箱**：脚本与产物只存在于 `research/experiments/`（`.gitignore` 已排除二进制），**永不进入生产镜像、Compose 依赖或用户安装步骤**。
- **可丢弃**：按 ADR-0006，属研究性 spike，须自我标注「可丢弃」。

### 5.3 人工验收（不可被脚本复跑的补充路径）

适用：脚本无法覆盖的观察项，如视觉观感、中文标点细节、WPS 弹窗行为。记录格式必须包含：验收人、日期、WPS 具体版本号、样本编号、逐项结论、失败截图。**人工步骤的结论不得被表述为「可复现的质量声明」**，两者在审计报告中分开呈现。

## 6. 版本记录纪律

目标软件版本号是**可复现质量声明的组成部分**。任何下列事件都必须新增矩阵版本记录，不覆盖旧记录：

- WPS 升级或更换（含补丁版本变化）；
- 未来引入 Microsoft PowerPoint 宿主（含版本与通道）；
- 校准系数取值变化（必须记录旧值、新值、触发原因与受影响样本）；
- 验收脚本探针序列变化。

## 7. 未决与后续

- **Microsoft PowerPoint 验收宿主**：当前无宿主，已按方案 A 接受。是否长期投入，留待总架构定稿时决定（见地图 `Not yet specified`）。
- **WPS 版本跨度**：11.8.2.8411 属较早期专业版，与新版个人版/专业版的行为差异未测；若目标用户多在较新版本，校准与探针需在新版本上复跑。
