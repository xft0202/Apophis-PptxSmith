# PPTX 质量优先的条件性路线结论（研究阶段）

- 日期：2026-09-27
- 性质：研究结论，不是 ADR，不授权实现或 benchmark
- 输入：S1-S5 代表性语义子集、P0/P2 硬门、官方能力资料、Spike E/D 证据

## 1. 结论先行

当前最可能满足高质量、原生可编辑、可交付 PPTX 的不是一个孤立 SDK，而是以下整体组合：

```text
语义中间层
+ 模板优先
+ 受控作者适配器
+ 包级对象/关系审计
+ 明确的作者版本与验收矩阵
```

这里必须区分两条正交轴：

- **作者轴**：谁负责创建/修改/保存 PPTX；
- **验收轴**：哪个软件和版本负责最终打开、编辑、保存、重开验收。

验收宿主会影响路线评分，但不能反过来把某个历史宿主预设为唯一作者。当前研究只保留两条真正值得进入下一阶段比较的作者路线：

1. **PowerPoint 原生作者**：PowerPoint 单宿主质量上限候选；
2. **独立语义 PPTX 作者**：Aspose 优先研究，Syncfusion/GemBox 作为并列备选。

WPS 不主导作者路线研究；但 `VISION.md` 已承诺 PowerPoint/WPS 均可继续编辑。若该承诺维持，WPS 必须作为独立的可编辑验收门，不能默认为只读或免验；若要收缩承诺，须由所有者显式批准。


## 2. 条件性排序

### 2.1 PowerPoint 单宿主质量上限

**第一候选：PowerPoint 原生作者 + 模板优先 + 语义中间层。**

理由：

- 作者和主验收宿主是同一个对象模型与保存引擎；
- 图表、ChartData.Workbook、表格、备注、母版和版式都有原生概念；
- 中文边界和 AutoFit 可以在目标宿主内直接测量和回归；
- 模板、主题和页面版式可由 PowerPoint 自身保存。

退出条件：

- 产品必须接受受控 Windows/PowerPoint 运行环境；
- 不能把 Microsoft 不支持的无人值守服务端自动化包装成普通 Linux 服务；
- WPS 只能作为另一个独立兼容门，不能共享 PowerPoint 的通过结论。

### 2.2 独立服务质量上限

**第一研究顺序：Aspose.Slides + 模板优先 + 语义中间层。**

理由不是“已经通过”，而是公开对象证据相对完整：

- chart workbook、worksheet/cell、公式和 series/category 引用资料较完整；
- 备注、母版、版式、富文本和 AutoFit 有公开 API；
- 可以独立运行和锁定服务端版本；
- 字体加载、嵌入、替换和 fallback 风险有公开说明，便于建立契约。

必须通过 S1-S5 的证据门：

- chart/workbook/cache 关系；
- 目标宿主编辑和保存重开；
- 未知部件/关系边界；
- 中文字体和 AutoFit 实际结果。

**Syncfusion** 是同等服务路线的并列研究候选：图表、备注、母版/版式和渲染覆盖广，但当前 embedded workbook 关系证据不如 Aspose 清晰。

**GemBox** 适合在模板保留和 unsupported feature preservation 维度比较，但本项目图表 workbook 关系仍需补证。

### 2.3 模板受控变更质量上限

**模板优先不是作者引擎，而是最重要的质量策略。**

当首期页面类型和品牌模板可控时，模板优先可以：

- 预先校准字体、内边距、行距和版式；
- 预先验证母版、主题、页脚和 Logo；
- 复用已经存在的原生图表和表格结构；
- 降低自由生成导致的关系、字体和布局漂移。

它不能替代作者引擎，也不能自动解决图表数据替换和未知部件保存。

## 3. 当前不进入主路线的形态

### WPS 原生作者

WPS 已有部分 WPP 对象模型证据，但仍未形成：

- embedded workbook 对象/关系契约；
- 备注写入和重存契约；
- 未知关系保留契约；
- 历史验收版本与当前 API 文档的完整映射。

因此当前定位是：**次级兼容宿主或待证作者适配器**，不是默认主路线。

### HTML/SVG/整页图片

直接退出最终作者候选：

- 不能满足原生图表、嵌入工作簿、原生表格和真文本；
- CSS 字体和浏览器布局不能作为 PPTX 中文字体契约；
- 视觉相似不能替代对象可编辑性。

### 仅低层 OOXML/高层通用库

作为包级保护、审计和局部补丁工具保留；没有 S1-S5 的对象和目标宿主证据，不承担首期整稿作者角色。

## 4. 当前唯一剩余决策门

当前不是继续扩展宿主或 SDK 名单，而是确认是否允许对以下两条作者路线做一次受控真实产物比较：

| 作者路线 | 最适合回答的问题 | 主要退出条件 |
| --- | --- | --- |
| PowerPoint 原生作者 + 模板优先 | PowerPoint 单宿主下能否达到最高 P0/P2 保真 | 无法接受 Windows/PowerPoint 受控环境，或 Office 自动化风险不可接受 |
| Aspose 优先的独立语义作者 + 模板优先 | 在服务化环境中能否达到同一 P0/P2 契约 | S1-S5 中 workbook、保存重开、未知边界或中文排版触发硬门 |

Syncfusion/GemBox 暂保留为第二梯队，不在没有比较授权前继续扩展研究。

验收宿主是评分轴，不是作者轴：

- PowerPoint 可以作为主验收宿主；
- WPS 不预设为作者，但只要维持现有双编辑产品承诺，就必须独立验收其编辑、保存和重开；
- 双宿主结果不能互相代表，失败须阻断该承诺或由所有者明确缩小交付范围。

**在所有者明确授权前，不写验证代码、不搭 benchmark、不运行引擎。**

## 5. 现阶段结果的置信边界

### 已经可以确定

- SANDUN 只能作为产品流程和规划层参考，不能作为最终导出引擎；
- P0 原生语义和 P2 中文真文本是硬门；
- 模板优先是跨路线的核心质量策略；
- PowerPoint 原生是 PowerPoint 单宿主的质量上限候选；
- Aspose 是当前独立服务路线中公开对象证据最完整的优先研究候选之一；
- WPS 不应继续主导整体路线判断。

### 尚不能确定

- 哪个候选在 S1-S5 的真实产物比较中全部通过；
- 商业 SDK 是否完整保留未知部件和关系；
- 中文字体和 AutoFit 在目标宿主中的长期稳定性；
- 双宿主是否能共享同一产物契约。

## 6. 下一步纪律

下一步不再扩大研究主题。只有在验收矩阵和产品承诺边界明确后，才允许：

1. 冻结同一模板、内容、数据、字体和 S1-S5；
2. 选择不超过两条最有希望的作者路线；
3. 由所有者明确授权真实产物比较；
4. 按 P0/P2 记录包级、宿主级和中文排版证据；
5. 触发通过、缩小支持范围或退出。

在此授权前，不写验证代码，不搭 benchmark，不宣布最终 SDK。

## 7. 吸收分类

| 对象/机制 | 吸收分类 | 边界 |
| --- | --- | --- |
| 语义中间层 + 受控作者适配器 | **适合二开** | 只覆盖 S1-S5 和真实 P0/P2 语义 |
| 模板优先 | **可直接复用** | 首期核心质量策略，不等于自由生成 |
| PowerPoint 原生作者 | **仅可借鉴** | PowerPoint 主宿主条件下的质量上限候选 |
| Aspose/Syncfusion/GemBox | **仅可借鉴** | 独立服务候选，必须过真实产物门 |
| WPS 作为次级兼容宿主 | **仅可借鉴** | 不反向决定整体作者架构 |
| HTML/SVG/整页图片最终导出 | **应当淘汰** | P0 原生语义硬冲突 |

## 8. 当前结论

> **当前最优整体路线假设是“语义中间层 + 模板优先 + 受控作者适配器”；下一阶段只比较 PowerPoint 原生作者与 Aspose 优先的独立语义作者。**

这不是最终 SDK 选择，而是基于现有 P0/P2 证据的最小、聚焦、可证伪路线集：

- PowerPoint 原生作者代表单宿主质量上限；
- Aspose 优先的独立作者代表服务化质量上限；
- Syncfusion/GemBox 保留为比较失败后的备选；
- WPS 不作为默认作者；若保留双编辑承诺则必须作为独立可编辑验收门；
- HTML/SVG/整页图片退出最终作者候选。

最终结论仍必须来自 S1-S5 的真实产物证据，而不是 API 文档或理论推断。
