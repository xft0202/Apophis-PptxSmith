# WPS WPP 对象模型一手证据（研究阶段）

- 日期：2026-09-26
- 性质：官方 API 证据整理，不是项目实测，不是最终选型
- 目的：修正 WPS 证据画像，区分“对象入口存在”和“PPTX 产物语义已通过”

## 1. 结论

本轮从 WPS 官方开放平台 `open.wps.cn` 的 WPP JSAPI 文档中确认了一组真实的演示对象入口。WPS 不应再被描述为“完全没有演示对象模型”。更准确的结论是：

> **WPS 的演示对象模型和常见编辑入口已有一手 API 证据；但原生图表关联嵌入工作簿、备注页可写语义、未知关系保留、版本支持和保存重开契约仍未达到本项目要求的证据等级。**

因此 WPS 从“证据不足候选”提升为“部分对象能力已证实、核心产物语义待证候选”，仍不能最终定案。

## 2. 已确认的官方 WPP 对象入口

### 2.1 演示文稿集合

官方 `Presentations` 对象页明确：

- `Presentations.Add` 创建新的演示文稿；
- `Presentations.Open` 打开演示文稿；
- `Presentations.Item` 获取指定演示文稿；
- 文档示例使用 `Presentation.Slides.Add` 添加幻灯片并使用 `Presentation.SaveAs` 保存为 PPTX。

来源：

- <https://open.wps.cn/documents/app-integration-dev/wps365/client/wpsoffice/jsapi/wpp/Presentations/obj>
- <https://open.wps.cn/documents/app-integration-dev/wps365/client/wpsoffice/jsapi/wpp/Presentation/obj>

### 2.2 幻灯片集合和版式

官方 `Slides`/`Slide` 对象页明确：

- `Slides.AddSlide` 创建幻灯片；
- `Slides.InsertFromFile` 从文件插入幻灯片；
- `Slides.Item` 获取单页；
- `Slides.Paste` 粘贴幻灯片；
- `Slide.Layout` 读写幻灯片版式；
- `Slide.Master` 获取该页关联的母版；
- `Slide.ApplyTemplate`、`Slide.ApplyTheme` 应用设计模板或主题；
- `Slide.Shapes` 获取页面元素集合；
- `Slide.NotesPage` 获取指定幻灯片或幻灯片区域的备注页入口。

来源：

- <https://open.wps.cn/documents/app-integration-dev/wps365/client/wpsoffice/jsapi/wpp/Slides/obj>
- <https://open.wps.cn/documents/app-integration-dev/wps365/client/wpsoffice/jsapi/wpp/Slide/obj>

### 2.3 演示文稿级母版、备注母版和自定义 XML

官方 `Presentation` 对象页列出：

- `Presentation.SlideMaster` 返回幻灯片母版；
- `Presentation.NotesMaster` 返回备注母版；
- `Presentation.CustomXMLParts` 返回与演示文稿关联的自定义 XML 部件集合；
- `Presentation.Fonts` 返回文稿使用的字体集合；
- `Presentation.SaveAs` 用于另存为不同名称/格式；
- `Presentation.Saved` 表示自上次保存以来是否发生改变；
- `Presentation.TemplateName` 返回关联设计模板或母版名称。

这些条目说明 WPS WPP API 不是只覆盖“新增几个形状”，而是暴露了演示文稿、母版、备注母版、字体和自定义 XML 等较高层对象入口。

但这些属性的存在**不等于**：

- 对应 OOXML 部件关系一定原样保留；
- 备注页文本一定可以通过当前 API 写入；
- 自定义 XML 与未知关系在保存后一定不变；
- PowerPoint/WPS 交叉保存一定一致。

## 3. 图表对象的已确认范围

官方 `Chart` 对象页明确：

- `Shape.Chart` 可取得形状中的图表；
- `Chart.SeriesCollection` 返回系列集合；
- `Chart.SetSourceData` 设置图表源数据范围；
- `Chart.ChartWizard` 修改图表属性；
- `Chart.DataTable` 返回图表数据表对象；
- `Chart.Refresh` 刷新图表；
- `Chart.ChartType`、`Chart.ChartTitle`、`Chart.PlotArea`、`Chart.Axes` 等图表对象属性可访问；
- `Chart.CopyPicture` 和 `Chart.Export` 提供图片复制/导出能力。

来源：

- <https://open.wps.cn/documents/app-integration-dev/wps365/client/wpsoffice/jsapi/wpp/Chart/obj>
- <https://open.wps.cn/documents/app-integration-dev/wps365/client/wpsoffice/jsapi/wpp/Shape/obj>

### 3.1 仍未确认的核心图表语义

在已读取的官方 `Chart` 对象页中，没有找到与 PowerPoint `ChartData.Workbook` 或 Aspose `IChartDataWorkbook` 同等级的以下明确对象入口：

- `ChartData.Workbook` 或等价的嵌入 Excel 工作簿对象；
- workbook worksheet/cell 级读写接口；
- 公式、series/category 对 workbook cell 的关系模型；
- embedded workbook part 的保存/重存保证；
- 图表缓存与嵌入工作簿同步的版本契约。

`SetSourceData` 只能证明 WPP 有设置数据源范围的 API 入口，不能单独证明：

1. 数据源是嵌入式 XLSX 而不是内部或外部范围；
2. PPTX 包中存在合法 embedded workbook 关系；
3. 缓存和 workbook 在 PowerPoint/WPS 重开后同步；
4. WPS 保存后关系闭包仍然完整。

## 4. 备注页证据边界

官方 `Slide.NotesPage` 已确认备注页入口，官方 `Presentation.NotesMaster` 已确认备注母版入口。

当前仍未确认：

- 备注页中的文本框/占位符是否有完整可写 API；
- 备注页与 slide 的关系是否在 SaveAs 后保持；
- WPS 重开时备注是否可见、可编辑；
- PowerPoint 打开 WPS 保存后的备注是否仍保留；
- 备注文本是否会被转换为评论、普通形状或被静默丢弃。

因此 WPS 的备注能力应记录为：

> **对象入口已证实；可写语义、关系闭包和跨宿主保存未证实。**

## 5. 母版、版式和字体证据边界

WPS 官方 API 已确认：

- presentation 级 `SlideMaster` 和 `NotesMaster`；
- slide 级 `Master`、`Layout`；
- `ApplyTemplate`、`ApplyTheme`；
- `Fonts`、`TemplateName`、`CustomXMLParts`。

这足以把 WPS 从“没有母版模型”的判断中移出。但仍未确认：

- master/layout/theme/placeholder 关系的完整读写接口；
- 未使用 layout/master 是否保留；
- 新增页是否始终继承目标版式；
- PowerPoint/WPS 互相保存后的主题、字体和 placeholder 关系；
- 中文字体 fallback、行高、断行和零溢出在固定版本中的稳定性。

## 5.1 版本识别与 API 可用性

WPS 官方 `Application` 对象提供 `Version` 和 `Build`，可在运行时读取客户端版本号与编译序号；官方 `canIUse` 机制用于判断当前客户端是否支持指定 API。这个机制有助于建立 WPS 版本门禁，但当前资料没有把本项目所需的 `ChartData.Workbook`、备注写入和关系保留契约映射到历史 WPS 11.8.2.8411，因此不能把“可读取版本/可检查 API”当成产物兼容性证明。

## 7. 对旧结论的修正

旧结论：

> WPS 只有少量 `wpp.execute` 线索，缺少演示对象模型。

修正后：

> WPS 官方 WPP JSAPI 已公开演示文稿、幻灯片、版式、母版、备注页、字体、自定义 XML、图表和保存入口；但图表嵌入工作簿、备注可写语义、未知关系保留、版本支持和目标宿主保存重开仍未形成项目所需的完整契约。

这意味着 WPS 不能继续按“没有对象模型”淘汰，也不能按“对象模型存在”宣布其满足原生 PPTX 交付。

## 8. 吸收分类

| 对象/机制 | 吸收分类 | 当前边界 |
| --- | --- | --- |
| WPS WPP `Presentations`/`Slides`/`Slide` 对象结构 | **仅可借鉴** | 用于继续研究和未来适配，不等于产物通过 |
| WPS `Slide.Layout/Master/NotesPage` | **仅可借鉴** | 入口已证实，关系和重存未证实 |
| WPS `Chart.SetSourceData/SeriesCollection` | **仅可借鉴** | 不替代 embedded workbook 证据 |
| WPS `Presentation.CustomXMLParts` | **适合二开** | 可作为审计/自定义数据入口，但保留未知关系仍需验证 |
| WPS 固定版本宿主 | **必须隔离** | 只有在版本、位数、字体和保存重开矩阵锁定后才能进入主路线 |
| WPS 官方用户指导中的“兼容 PPTX” | **仅可借鉴** | 不是对象级或关系级验收证据 |
| 把 WPP API 存在等同于原生 PPTX 已通过 | **应当淘汰** | 违反对象—关系—缓存—宿主四层证据规则 |

## 9. 当前结论

WPS 现在是一个有真实一手对象模型证据的条件性候选，而不是“完全证据不足”的候选。

但它距离主路线仍缺四个关键证据：

1. `Chart` 到 embedded workbook 的完整对象/关系模型；
2. 备注页写入、保存和 PowerPoint/WPS 重开；
3. master/layout/theme/placeholder 关系闭包与未知部件保留；
4. 精确版本、位数、字体和自动化部署契约。

在这四项完成前，WPS 不能与 PowerPoint 原生、Aspose、Syncfusion、GemBox 做最终同等级定案。
