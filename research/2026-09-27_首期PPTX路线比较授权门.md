# 首期 PPTX 路线比较授权门（研究阶段）

- 日期：2026-09-27
- 性质：比较前的边界与记录规则，不是实现授权，不是引擎决策
- 适用范围：S1-S5 代表性语义子集和 P0/P2 硬门

## 1. 进入比较前必须冻结的内容

任何真实产物比较开始前，以下内容必须保持不变：

### 1.1 输入

- 同一份中文商务汇报内容；
- 同一组数字和图表数据；
- 同一份品牌模板；
- 同一组字体文件和字体 hash；
- 同一份备注文本；
- 同一组页面角色：S1-S5。

不允许为某条路线删减图表、缩短中文、改用图片或换模板来规避失败。

### 1.2 产物承诺

所有路线都按同一 P0/P2 契约判断：

- 原生图表；
- 合法嵌入工作簿和缓存关系；
- 原生表格；
- 真文本；
- 原生图片；
- 备注页；
- 母版/版式/主题；
- 中文混排和零溢出；
- 目标宿主保存重开；
- 对象、关系、字体和来源审计。

### 1.3 作者路线与共同策略

共同策略不是独立作者候选，而是两条作者路线都必须采用的质量约束：

- 语义中间层；
- 模板优先；
- 受控作者适配器；
- 包级对象/关系审计。

本轮只比较两条作者路线：

1. **PowerPoint 原生作者**；
2. **独立语义 PPTX 作者**，优先研究 Aspose，Syncfusion/GemBox 作为并列备选。

HTML/SVG/整页图片只作为预览或设计辅助，不进入最终作者比较。

WPS 不主导作者路线；但 `VISION.md` 已承诺 PowerPoint/WPS 均可编辑。若此承诺维持，WPS 必须作为独立的编辑、保存、重开验收门；若要收缩承诺，须由所有者明确批准。WPS 作者适配器仅在业务明确要求时另行研究。

作者路线与验收矩阵必须分别记录：作者引擎、作者运行时、主/次级宿主、版本、是否允许保存回流。

## 2. 每条路线必须提交的记录

### 2.1 路线坐标

- 架构形态；
- 作者引擎和精确版本；
- 作者运行时和操作系统；
- 模板/母版/字体版本；
- 主验收宿主、次级宿主和是否允许保存回流；
- 许可证和部署边界。

### 2.2 S1-S5 结果

| 页面 | 关键对象 | 必须有的结果 |
| --- | --- | --- |
| S1 | 真文本、母版、版式、字体 | 包级存在、可编辑、无中文溢出、重开稳定 |
| S2 | KPI 真文本、混排、数字 | 字体映射、行高、边界、无裁切 |
| S3 | chart、workbook、缓存、中文标签 | 关系闭包、数据编辑、缓存同步、重开一致 |
| S4 | `<a:tbl>`、单元格、表格文字 | 原生表格、改格/增行持久、无裁切 |
| S5 | notes、master/layout、主题 | 备注正确、继承正确、保存重开稳定 |

### 2.3 证据包

每条路线的记录必须至少包含：

- PPTX hash；
- 包部件清单；
- relationship 清单；
- chart/workbook 对照；
- notes/master/layout 清单；
- `<a:t>`、`<a:tbl>`、`<p:pic>` 和 chart 统计；
- 字体 typeface、East Asian 字体和嵌入状态；
- 目标宿主打开/编辑/保存/重开记录；
- 中文预测和实际渲染记录；
- 失败对象及退出判断。

只给截图、PDF 或厂商功能页，不能构成比较结果。

## 3. 结果分类

每个能力只允许使用以下状态：

| 状态 | 含义 |
| --- | --- |
| `official` | 官方资料明确存在 API/功能，但未证明本项目产物 |
| `package-verified` | PPTX 包和关系已检查 |
| `host-verified` | 指定宿主已打开、编辑、保存、重开 |
| `regression-verified` | 多页、多中文样本、多次运行均稳定 |
| `unknown` | 没有足够证据 |
| `blocked` | 已触发硬否决或明确不支持 |

比较报告不得把 `official` 写成 `host-verified`，也不得把 `unknown` 写成“应该支持”。

## 4. 退出与降级规则

### 4.1 直接退出主作者候选

- S1-S5 任一承诺对象触发 P0 硬否决；
- 图表只有视觉结果，没有合法 workbook 关系；
- 表格、备注或真文本被图片化；
- 中文出现无法解释的裁切、缺字或静默缩字号；
- 保存重开后核心对象或关系消失；
- 只能通过 PDF/PNG 证明质量，不能证明 PPTX 可编辑。

### 4.2 可以缩小支持范围

- 只支持一个明确主宿主；
- 只支持固定模板和页面角色；
- 只支持固定字体包；
- 明确禁用尚未证明的图表类型或复杂对象；
- 将旧稿局部修改列为 D 类延期，而不是首期承诺。

### 4.3 不能接受的“通过”方式

- 通过改变输入内容规避长中文；
- 用图片替代失败的图表、表格或备注；
- 用 PDF 截图替代 PPTX 对象证据；
- 用一个宿主的结果代表另一个宿主；
- 用 API 文档、营销页或单张截图替代保存重开；
- 把“用户看不出差异”当作原生语义通过。

## 5. 比较终点

只有当候选进入 `host-verified`，并且 S1-S5 的 P0/P2 都没有硬失败，才进入下一层排序：

1. 模板保留和品牌一致性；
2. 审计和可复现；
3. 运行成本和部署；
4. 许可证和支持；
5. 升级、回滚和替换路径。

在此之前不做综合评分，不用工程便利抵消产物失败。

## 6. 当前允许的下一步

当前研究阶段只允许：

- 审阅本授权门；
- 冻结 S1-S5 的内容、模板和字体输入；
- 冻结作者版本、双编辑产品承诺边界与验收矩阵（主/次级宿主、build、编辑和保存回流规则）；
- 决定是否授权进入真实产物比较。

当前不允许：

- 扩展 WPS API 研究成为主线；
- 增加新的候选名单；
- 为某个 SDK 提前搭实现工程；
- 用 benchmark 结果替代未完成的需求边界；
- 宣布某个引擎为最终答案。

## 7. 吸收分类

| 对象/机制 | 吸收分类 | 边界 |
| --- | --- | --- |
| S1-S5 固定比较子集 | **可直接复用** | 作为所有路线的共同输入和判据 |
| `official/package-verified/host-verified/regression-verified` 证据分层 | **可直接复用** | 防止把厂商声明写成项目通过 |
| P0 硬失败退出规则 | **可直接复用** | 任何候选都不得绕过 |
| 主宿主和字体/模板冻结 | **适合二开** | 进入未来验证流程和版本契约 |
| PDF/截图替代 PPTX 语义 | **应当淘汰** | 不能作为比较通过条件 |
| 继续扩展无关宿主或候选 | **应当淘汰** | 违反当前聚焦范围 |

## 8. 当前结论

> **路线比较已经有固定入口和退出点：先冻结 S1-S5、作者版本和验收矩阵，再比较两条作者路线的 P0/P2；任何承诺对象失败就退出主作者候选。**

本文件不授权实现、不授权 benchmark、不选择最终引擎。
