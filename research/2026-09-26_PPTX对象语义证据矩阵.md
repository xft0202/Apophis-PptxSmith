# PPTX 对象语义证据矩阵（研究阶段）

- 日期：2026-09-26
- 性质：纯研究，不是实现规格，不授权 benchmark，不宣布引擎
- 目标：把“支持 PPTX/支持图表”拆成可审查的对象、关系、缓存、宿主行为和版本问题

## 1. 证据等级

| 等级 | 含义 |
| --- | --- |
| 官方 API/规范明确 | 一手资料明确出现对象、属性、方法或格式声明；只能证明供应商/规范如此声明 |
| 官方功能说明 | 官方页面描述能力，但对象关系或保存细节未完全展开 |
| 项目已实测 | 本项目固定版本、固定模板、固定输入和目标宿主已验证 |
| 未知 | 当前资料不足，不能正面或负面推断 |
| 反向风险 | 官方资料明确提醒规范化、遗漏、显示差异或宿主限制 |

**规则**：官方 API/功能说明永远不自动升级为“项目已实测”。

## 3. 关键拆分：图表不是一个断言

“支持原生图表”至少要拆成：

1. PPTX 包中存在 chart part；
2. slide 与 chart part 的关系正确；
3. chart part 与 embedded workbook 的关系正确；
4. workbook 内容与 series/category 引用一致；
5. cached values 与 workbook 一致；
6. PowerPoint/WPS 打开后显示一致；
7. 在目标宿主中编辑数据后仍可保存和重开；
8. SDK 再次保存后没有丢失 workbook、关系或未知部件。

因此：

> `IChartDataWorkbook`、`ChartData`、`OfficeChart` 或任何 `AddChart` API 只能证明对象模型入口，不能独立证明上述八项全部成立。

## 4. 关键拆分：备注不是“文本存在”

备注验收至少要拆成：

- notes slide part 存在；
- slide relationship 正确；
- notes text frame 内容正确；
- notes master/style 是否保留；
- PowerPoint/WPS 是否能看到和编辑；
- SDK 重存后 notes part 和关系是否仍在；
- 备注不应被误判为普通 slide text 或评论对象。

## 5. 关键拆分：母版不是“有模板文件”

母版验收至少要拆成：

- presentation 对 master 的关系；
- master 对 layout 的关系；
- slide 对 layout 的关系；
- theme、字体和颜色继承；
- placeholder 类型和索引；
- 新增页是否使用正确 layout；
- 未使用但仍属于模板的 layout/master 是否保留；
- PowerPoint/WPS 重存后是否重写或丢失继承关系。

## 6. 当前候选的证据画像

### PowerPoint Desktop

- **强项**：PowerPoint 自己的对象模型和保存引擎；图表、工作簿、备注、母版、版式均有原生概念。
- **未知**：WPS 交叉保存；服务端无人值守稳定性；固定 Office build 之外的升级行为。
- **结论**：PowerPoint-first 的宿主保真潜力最高，但不能自动外推到 WPS 或 Linux 服务。

### Aspose.Slides

- **强项**：本轮官方资料对 `IChartDataWorkbook`、公式、series/category cell 引用、notes slide、master/layout 的对象证据最完整。
- **风险**：官方明确提醒不支持/特殊内容可能规范化、遗漏或显示差异；嵌入 workbook 的项目关系、缓存、PowerPoint/WPS 重开仍未实测。
- **结论**：独立 SDK 中对象级公开证据最完整之一，但不是项目通过。

### Syncfusion Presentation

- **强项**：图表 DOM、notes slide、notes-page 转换、master/layout API 和富文本模型公开资料较完整。
- **风险**：当前未拿到与 Aspose `IChartDataWorkbook` 同等级的 embedded workbook 证据；unsupported parts 保留和跨宿主保存未证。
- **结论**：API 覆盖广，但图表 workbook 和保留边界仍是硬问题。

### GemBox.Presentation

- **强项**：`NotesSlide` 类型和 unsupported feature preservation 声明；开发者授权和跨平台渲染路线也较清晰。
- **风险**：本轮抓取的两个图表/母版示例页面发生标题错配，不能据此声称图表 workbook 或完整 master/layout 语义；需要准确文档入口或项目产物证据。
- **结论**：保留策略有亮点，但对象级图表和模板继承证据需要补齐。

### WPS

- **强项**：WPP JSAPI 已有 `Presentations`、`Slides`、`Slide.Layout/Master/NotesPage`、`Presentation.SlideMaster/NotesMaster/CustomXMLParts`、`Shape.Chart` 和 `Chart.SetSourceData` 等官方对象入口。
- **风险**：当前仍未找到与 PowerPoint `ChartData.Workbook` 或 Aspose `IChartDataWorkbook` 同等级的嵌入工作簿对象；备注可写语义、关系闭包、未知部件保留、版本支持和双宿主保存仍未证。
- **结论**：WPS 已从“完全缺少对象模型”修正为“对象模型部分已证实、核心产物语义待证候选”，不能按旧结论淘汰，也不能宣布通过。

## 7. 必须避免的错误推理

| 错误推理 | 正确改写 |
| --- | --- |
| SDK 有 `AddChart`，所以是原生图表 | 只证明 API 能创建图表；还要证明 chart part、workbook、缓存、目标宿主行为 |
| 能编辑 workbook，所以嵌入关系正确 | 还要检查 PPTX relationships、content types、embedded file 和重开结果 |
| 有 `NotesSlide` 类，所以备注通过 | 还要检查 notes part、关系、内容、重存和宿主可见性 |
| 有 Master/Layout API，所以模板保留通过 | 还要检查 master/layout/theme/placeholder 关系闭包 |
| 有 preservation 声明，所以未知部件安全 | 只能记录官方声明；必须用未知部件/关系夹具实测 |
| PowerPoint 能打开，所以 WPS 也等价 | 两个宿主必须分别打开、编辑、保存、重开 |

## 8. 吸收分类

| 对象/机制 | 吸收分类 | 边界 |
| --- | --- | --- |
| “对象—关系—缓存—宿主”四层验收拆分 | **可直接复用** | 作为项目验收矩阵结构 |
| Aspose `IChartDataWorkbook` 等对象级 API 文档 | **仅可借鉴** | 证明 API 入口，不证明项目产物 |
| Syncfusion notes/master/layout DOM | **仅可借鉴** | 证明公开能力，不证明关系闭包和跨宿主保存 |
| GemBox preservation 声明 | **仅可借鉴** | 必须用未知部件/关系夹具验证 |
| WPS 历史 Spike E 结果 | **适合二开** | 只能作为固定版本验收夹具和回归样本 |
| “支持 PPTX/支持图表”笼统标签 | **应当淘汰** | 不满足对象语义审查要求 |
| SANDUN 的整页 SVG/形状拼图 | **应当淘汰** | 不满足原生对象目标 |

## 9. 当前结论

截至本轮：

- Aspose 的官方对象级证据最完整，但仍未证明本项目的 embedded workbook、缓存、未知部件和双宿主重开；
- Syncfusion 的图表、备注、母版/版式 API 证据充分，但 embedded workbook 和未知内容保留仍未证明；
- GemBox 的 preservation 与 notes API 有价值，但图表 workbook 和母版页面证据需要校正；
- PowerPoint 原生宿主保真潜力仍最高，但服务端和 WPS 交叉风险不变；
- WPS 仍属于证据不足路线。

**没有任何候选因为本矩阵而获得最终选型资格。**
