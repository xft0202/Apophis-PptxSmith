## 一、结论与证据边界

四条产品架构路线都有支撑候选价值的机制，但承担的修改、交付与维护责任不同；不能凭某个库能写 PPTX，就认定完整应用可行。条件性建议是：围绕材料变化、局部修改、交付后编辑比较完整工作链，再决定主表达与辅助组件，而不是先选语言、数据库或文件引擎。

已完整阅读指定的五份本地文档；未读取删除报告或 Git 历史，未继承旧排序。用户不限身份、任务可自由组合；SANDUN仅作为交互流程、视觉、材料内容、交付修改四维参考，不推导整体复制。子调查没有Context7工具，采用官方网页与仓库正文；父代理补用了Context7定位python-pptx官方资料（第八节）；没有运行产品/SDK、安装、登录、模型生成、Windows链或 Presenton重试。

下文 **事实** 指已读一手正文，**解释** 指对来源适用边界的理解，**推断** 指本项目责任与建议。子调查读取动态分支/网页；父代理随后补做固定提交、包元数据与关键正文复核，见第八节。python-pptx的stable页显示 **0.6.22**，latest页显示 **1.0.0**，PyPI元数据为 **1.0.2**，文档、分支和分发版本不能混称。Docling文档中的最低Python版本与本次release快照分开记录。Slidev固定提交中存在可编辑导出分支，但没有实际运行或产物验证。[3][12][16–19]

## 二、R1–R9：从需求到技术责任

沿用候选需求编号，**以下技术责任全部是研究推断，不是用户规格**。成本、维护与失败接手横跨各项，不另造需求排序。

| 编号／需求 | 需要承担的技术责任 | 轻条件 → 重条件 |
|---|---|---|
| R1 材料组织 | 提取阅读顺序、表格/图像，保留原文位置、疑点和来源关联 | 人工检查单材料 → 多格式OCR、长材料冲突、跨材料依据 |
| R2 目的/听众改编 | 模型接入、目标与上下文管理，区分事实、改写与创作；失败可转人工 | 用户确认一次改写 → 多轮目标变化与一致性检查 |
| R3 局部修改/恢复 | 对象身份、作用范围、差异、快照、撤销；处理文字变化引发重排 | 页级副本 → 对象级历史、影响传播与外部编辑合并 |
| R4 旧稿/资产复用 | 导入对象与关系、保留原稿、标明降级；模板和素材许可 | 提取内容/参考样式 → 原结构修改与复杂对象保留 |
| R5 数据及解释更新 | 数据—图表—结论关联、失效检测、更新确认 | 指定对象人工更新 → 跨页联动、图片图表恢复数据 |
| R6 视觉调整 | 内容与样式关联、页面表示、排版、字体、预览和导出对应 | 源稿内调整 → 双表示映射、任意布局与迁移 |
| R7 合适交付 | 对象粒度声明、格式转换、降级报告、交付后接续 | 阅读/播放 → 原生数据编辑、重新导入与差异合并 |
| R8 自动化程度/入口 | 应用状态、暂停/取消、步骤检查点、重试、手工接手 | 本地单任务 → 并发、跨会话恢复、外部服务变更 |
| R9 可检查反馈改稿 | 意见到对象的映射、变更说明、冲突保留 | 单稿反馈 → 多人权限、并行版本与审批 |

Docling的统一结构、文件引擎的对象图、模型返回的JSON只是可处理表示；**均不证明事实正确、材料完整或改写获授权**。[1][3][6][12] 这也是R1/R2不能被“schema验证通过”替代的责任解释。

## 三、产品架构路线：并列比较，不预设排名

| 网页主表达，按用途导出 | 网页视觉和交互作为源稿；源内修改后重新导出。Slidev是代表，不是完整产品。[10] | 图片导出较直接；可编辑导出需要浏览器→文件对象映射。网页预览不等于办公软件版式；导出后外部编辑不自动回源 | 只播放/阅读、网页交互优先时有竞争力；若交付后频繁改数据与结构，文件或作者环境路线可能更合适 |

| 复用既有应用＋可替换组件组合 | 既有应用接住入口/状态/编辑，替换提取、模型或导出部件；也可只复用某段机制 | 不能仅凭一个导出API认定整个应用可替换。须审查状态格式、扩展接口、迁移、许可、上游升级；二开可能绑定其页面表示 | 已有工作链符合目标且接口稳定时可少建应用层；若修改牵动前后端和存储全链，独立组合或作者环境辅助可能更低耦合 |

## 五、编辑层级、应用责任与建议

五种能力应分别记录：**原生编辑**指文字/图表数据等对象语义；**形状编辑**可能只有位置颜色或拆散图元；**图片编辑**可移动裁切，不等于修改图中文字；**应用内编辑**只说明源应用能改；**PPTX往返**还要求外部保存后的变更能被重新识别、保留或合并。Slidev可编辑导出声明的是部分形状能力，不证明原生图表或往返。[10] python-pptx的读写也不自动解决外部改稿后的应用状态合并。[3][4]

下列是**研究推断**：无论何种路线，应用都要管理任务/页/对象身份、材料版本、人工改动和生成状态；模型适配要处理上下文、结构验证、拒绝/超时/截断、取消与重试，保留可编辑中间结果。只保留最后文件无法解释哪些页依赖已变化材料；盲目重试可能重复计费或覆盖人工修改。文件生成器不提供这些完整责任，数据库、耐久工作流和多账号也不是必选答案。[1][4][6]

轻方案可采用单任务、明确快照、人工接手与源稿重新导出；多轮/并发/外部编辑合并才可能需要更重状态机制。网页预览与文件输出采用两套表示时，应声明对应与回退；即使Aspose能同引擎保存并渲染，也不能证明接收端同版式。[8][10]

条件性建议：把“网页源稿＋按用途导出”“文件对象＋材料组织”“现有作者环境＋辅助”视为竞争备选；若既有应用状态和编辑模型适合，再考虑二开组合。若主要收益来自视觉迭代且交付只播放，网页可优先进入待授权比较；若收益来自旧稿/数据连续修改，则文件/宿主方案应进入同题比较。新增可编辑网页导出可能削弱“网页必然只能图片”的判断，但复杂元素回退、换行及外部修改仍可能反转选择。[3][8][10][14] 不宣布产品形态、引擎、语言或DB已选。

## 六、矛盾、缺口与待授权最小验证

1. **措辞张力**：python-pptx同时说任意Open XML往返和仍有不支持特性；合理解释是保留已有内容与提供编辑API不同，而非采信任意修改无损。[3] PptxGenJS README同时写JSZip打包依赖和“zero runtime dependencies”，需核对实际分发包，不据宣传判无依赖。[1]
2. **检索与正文差异**：Slidev搜索摘要突出图片导出，但实际正文有可编辑模式；Aspose检索摘要曾描述提取限制为“一页”，当前Licensing正文为文本截断，本文以正文为准。[9][10] 未发现可用于效果排序的直接对照证据。
3. **待授权验证，不执行**：选一份有表格、图表、长中文和复杂视觉的材料/旧稿，在候选路径完成一次修改和交付后再改；记录事实核对、对象回退、字体/换行、恢复、人工接手、总返工及真实资源支出。样例是探测工具，不是任务白名单；不设价格、工期、成功率猜测。Office路线若涉及账号/运行，须另授权，不能重建Windows链。
4. **材料变化反例（假设）**：源表更正数据，图表数字更新了，但概述仍说“增长”。JSON/文件都合法，仍可能交付错误；验证必须观察关联、失效提示和人工确认，而不是只看导出成功。
5. **交付后编辑反例（假设）**：收件人把PPTX图片页中的数字换成文本框，或移动导出的形状后回传；源应用重导出覆盖这些改动。即使图片可移动、形状可改，V1修改连续性仍可能不成立。

风险尚包括事实核对增负担、源稿与交付分叉、局部改动连带重排、依赖/许可与字体变化。仍缺实际分发包与执行版本验证、完整源码级不支持清单、同题渲染和往返证据、完整商业合同及实际维护数据。价值、范围、预算和立项标准交由用户与整合报告决定。

- **网页路线不应被预先等同于图片PPTX**：固定提交 `30a0a54c8739b4b395d9b336a6304cc8ebcc3947` 的 [Slidev说明 L75–95](https://github.com/slidevjs/slidev/blob/30a0a54c8739b4b395d9b336a6304cc8ebcc3947/docs/guide/exporting.md#L75-L95) 声明可编辑导出；[导出入口 L220–225](https://github.com/slidevjs/slidev/blob/30a0a54c8739b4b395d9b336a6304cc8ebcc3947/packages/slidev/node/commands/export.ts#L220-L225) 将普通图片路径与 `genPagePptxEditable` 分开。这里只证明声明与入口分支存在，未审完整映射算法、未运行，也不保证任意页面或原生图表。字体、换行、复杂元素图片回退仍是正文明确的限制。[19]
- **python-pptx的文档与包版本分开**：父代理读取 [latest首页](https://python-pptx.readthedocs.io/en/latest/index.html)（标1.0.0），通过 [PyPI元数据](https://pypi.org/pypi/python-pptx/json) 观察分发版本1.0.2、Python要求>=3.8；没有安装或以旧stable页限定当前全部API。Context7查询 `/scanny/python-pptx` 后定位到官方 presentations.rst 和 Feature Support；检索摘录不用于保证无损往返。[16–17]
- **结构契约不是事实契约**：模型接入可用结构化结果降低解析负担，但官方文档明确仍可能包含错误。拒绝、截断/未完成与失败需要分别处理，不由schema或HTTP状态判断稿件已经可用。此例不代表选定OpenAI、模型或供应商。[18]
- **许可证分层**：回看Office.js条款，使用限于与Microsoft365互操作的Authorized Apps，分发代码有不得修改等条件；Aspose未授权时存在逐页水印与读取文本截断。两者不是因别的代表库是MIT就可统一推导授权，最终合同和依赖审查尚待进行。[9][15]
