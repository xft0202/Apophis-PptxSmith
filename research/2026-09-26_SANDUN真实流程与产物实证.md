## 3. 图表计划的真实结构（重要证据，并修正此前结论）

`chart_plans` 里保存的是**结构化图表数据**，而不是渲染结果：

```json
{
  "page-1zbl1xvq": [{
    "chart_type": "bar",
    "data": [
      {"color": "#2563EB", "label": "A股半导体设备指数", "value": 130.87},
      {"color": "#94A3B8", "label": "海外设备龙头平均", "value": 53.5}
    ],
    "has_chart": true,
    "module": 2,
    "reason": "两组同为PE估值口径的对象可直接比较，能够突出A股设备板块相对海外龙头的估值溢价与容错不足",
    "slot_id": "chart-1",
    "style": {"fontColor": "#64748B", "fontSize": 13,
              "showLegend": false, "showValues": true, "unit": "倍PE（TTM/平均）"}
  }]
}
```

**修正此前的结论（两处）**：

**修正一：`chart_plans` 不是空的。** 我此前基于 4 份公开回放数据判断
「`chartPlans`/`imagePlans`/`diagramPlans` 全部为空」，**现在看那是旧案例的状态**：

| 对比项 | 4 份公开回放案例 | 本次实测新项目 |
| --- | --- | --- |
| 项目创建时间 | 2026-03-11 ~ 2026-03-24 | 2026-09-26 |
| `chart_plans` | `{}` 空 | **11 个页面有内容** |
| `image_plans` | `{}` 空 | 11 个页面有内容 |
| `diagram_plans` | `{}` 空 | 11 个页面有内容 |

且新流程的 `data[]` 里是**语义化的数值 + 单位 + 标签 + 理由**，是真正的数据模型。
所以「它的图表只是渲染产物」这个判断**对规划层不成立**，我此前说重了。

**修正二：真正的问题在导出环节。** 结构化数据在规划层存在，但导出时没有被还原成
OOXML 原生图表。这一点由下一节的产物解包实测确证。

另外，公开回放接口与实时状态接口**字段口径不同**（回放用 `chartPlans`+SVG `content`，
实时用 `chart_plans`+`drafts`），因此**不能用回放的空字段推断它当前的能力**——
这是本次踩到的教训：**旧快照不能代表当前实现**。

## 5. 结论：结构化数据在导出环节丢失

**这是本次实测最重要的发现，且修正了我此前的一个判断：**

| 层级 | SANDUN 的实际状态 |
| --- | --- |
| **规划层** | ✅ **有**结构化图表数据（`chart_type` / `data[{label,value,unit,color}]` / `reason` / `slot_id` / `style`） |
| **导出层** | ❌ **全部丢失**。产出 0 个 chart part、0 个嵌入工作簿、0 个原生表格、0 张图片 |
| **用户拿到的** | 411 个**形状** + 307 个**文本 run**，图表被**展平成形状拼图** |

**所以准确的结论是**：

> SANDUN 的图表**不是没有数据模型**——它在规划层有。
> 问题出在**导出**：SVG 是中间表示，导出时**没有把结构化数据还原成 OOXML 原生图表**，
> 而是把 SVG 图元**逐形状转成 PPTX 形状**。

**后果（对用户）**：

1. 在 PowerPoint/WPS 里**改不了图表数值**——那些柱子是形状，不是图表，双击没有数据表；
2. 表格**改不了行列**——没有 `<a:tbl>`，是形状拼的；
3. `system-ui` 字体族会被静默替换，中文版式可能走样；
4. 无嵌入字体 → 它文档里说的「请先在目标电脑安装字体」正是因为这个。

**这比我此前"结构性缺陷"的判断更精确**：缺陷不在数据建模，而在**导出保真**。
它的规划层是值得学的；它的导出层是我们能明确超越的地方。

## 7. 需要吸收的设计（实测确认）

1. **风格推荐带 `style_reason`**：每套风格给一段面向用户的、有审美的设计说明，
   而不是「风格 A / 风格 B」。这直接提升用户的选择信心。
2. **7 阶段流水线**：比我们的 4 道门多出「内容策划」与「风格选择」两个高价值卡点。
3. **`chart_plan` 的 `reason` 字段**：为每张图说明「为什么用这个图表类型」，
   可核验、可审计——这正是我们「可核验证据」想做但还没做的形态。
4. **导出分段进度**：`buildPptxExportSteps` 明确定义四个阶段
   （整理页面 → 下载素材 → 生成页面 → 导出上传），带 `maxActiveJobs/Renders` 并发控制。
5. **需求单 30 秒自动提交默认值**：不阻塞流程，且默认值合理。
