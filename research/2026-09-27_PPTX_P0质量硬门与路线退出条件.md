# PPTX P0 质量硬门与路线退出条件（研究阶段）

- 日期：2026-09-27
- 性质：质量裁判规则，不是 ADR，不授权实现或 benchmark
- 目标：在继续比较作者路线前，明确什么失败必须退出，什么风险可以延后

## 1. 唯一裁判对象

候选不是因为“有 API”“能生成 PPTX”或“能渲染 PDF”而通过。

候选必须证明自己能在指定版本契约下交付：

```text
原生对象
+ 合法关系
+ 可编辑行为
+ 中文真文本
+ 目标宿主重开
+ 可审计产物
```

## 2. P0 硬否决条件

以下任一项在候选的承诺对象上失败，路线必须退出主作者候选，不能用视觉效果或工程便利补偿。

### 2.1 原生对象失败

- 原生图表被输出为整页图片、SVG 或形状拼图；
- 图表没有可证明的合法数据关系；
- 图表承诺包含嵌入工作簿，但产物没有 workbook 部件或关系；
- 原生表格变成文本框、形状网格或图片；
- 真文本变成图片或不可选中的图形；
- 备注页缺失，或备注内容无法在承诺宿主中读取；
- 模板承诺的母版/版式/主题继承被静默破坏。

### 2.2 关系与持久化失败

- chart part、workbook、slide 或 notes relationship 悬空；
- 改图表数据后 workbook、缓存和显示结果互相矛盾；
- 打开、编辑、保存、重开后核心对象消失或变形；
- SDK/宿主保存后未知或未授权部件被静默删除，且路线无法明确隔离这些部件；
- 产物不能通过 OOXML 包和关系闭包检查。

### 2.3 零图片化失败

承诺对象的图片化属于硬否决，不接受“图片看起来一样”“用户可以替换整页图片”或“形状仍然可以移动”作为替代解释。

### 2.4 中文真文本失败

- 中文、英文、数字或标点出现缺字、乱码或错误字体；
- 文本溢出、裁切或遮挡；
- 字体 fallback/substitution 或缩字号发生但没有记录；
- 生成器预测与目标宿主实际排版长期不一致；
- 关键字体依赖目标机器随机存在，且没有可审计替代路径。

## 3. P1 条件门

P1 不一定立即淘汰整个作者形态，但在承诺该能力时必须阻断交付或缩小支持范围。

| 条件 | 允许的处理 | 不允许的处理 |
| --- | --- | --- |
| 只支持 PowerPoint，不支持 WPS | 明确声明 PowerPoint-only | 宣称双宿主兼容 |
| 只支持固定模板和页面角色 | 把模板范围写入产品契约 | 宣称任意自由生成 |
| 只支持固定字体包 | 随产物/部署提供字体和 hash | 依赖用户本机字体碰运气 |
| 某类图表没有 workbook 关系 | 禁止该类图表，或降级为明确的非承诺对象 | 静默输出图片/形状并标记为原生图表 |
| 备注只读 | 明确只读范围 | 宣称备注可编辑 |
| 未知部件无法保留 | 首期隔离受控补丁范围 | 对既有复杂模板无条件重存 |
| 自动适配会缩字号 | 设定最小字号和阻断规则 | 为避免溢出无限缩小文字 |

## 4. P2 中文排版门

中文排版不应只用“有没有溢出”一个布尔值判断。必须记录：

- 字体文件、版本、许可和 hash；
- Latin/East Asian/Complex Script 字体映射；
- 文本框宽高和四边内边距；
- 段前、段后、行距和换行策略；
- `normAutofit`、`spAutoFit` 或 `noAutofit`；
- 预测行数、边界宽高和安全余量；
- 目标宿主实际行数、边界和裁切情况；
- 混排、标点、图表标签、表格单元格和备注样本。

### 4.1 自动适配的三种不同语义

- `normAutofit`：可能通过缩小字体或减少行距解决溢出；必须有最小字号和减距上限；
- `spAutoFit`：可能扩大形状并破坏固定页面布局；不能用于不允许改变页面结构的对象；
- `noAutofit`：保持尺寸但可能溢出；适合由量字规划提前保证安全余量的对象。

因此“开启 AutoFit”不是通过条件。必须记录具体语义和结果。

## 5. 可延期的 D 类风险

以下问题在首期不一定否决整稿生成，但必须记录，并限制未来受控补丁范围：

- 未知部件和未知关系不能原样保留；
- 只支持从模板生成新稿，不支持打开旧稿局部修改；
- 只能保留模板中未被作者引擎重写的部件；
- 只能对授权对象做替换，不能保证任意 OOXML 部件字节不变。

但以下情况不能借 D 类延期掩盖 P0 失败：

- 新稿中的原生图表、工作簿、表格、备注或真文本缺失；
- 目标宿主重开后核心对象消失；
- 中文文字溢出或图片化；
- 关系闭包不合法。

## 6. 证据阶梯

每个硬门必须标注证据等级：

| 等级 | 能证明什么 | 不能证明什么 |
| --- | --- | --- |
| 官方 API | 对象或操作入口存在 | 项目产物、关系闭包、中文排版和目标宿主行为 |
| 官方功能声明 | 供应商宣称支持某能力 | 本项目固定版本是否稳定 |
| 包级检查 | 部件、关系和类型存在 | 目标软件是否能编辑和保存 |
| 目标宿主实测 | 固定输入在固定宿主中的行为 | 所有版本、字体和页面角色 |
| 保存重开实测 | 一次完整持久化闭环 | 无边界版本泛化 |
| 多模板/多字体回归 | 支持矩阵中的稳定性 | 未覆盖对象和宿主 |

**规则**：P0 通过至少需要包级证据 + 目标宿主打开/编辑/保存/重开证据；只读 API 或官方宣传不能通过。

## 7. 对架构形态的裁判结果

### 7.1 目标宿主原生作者

- 最容易满足该宿主的 P0 对象语义；
- 仍必须接受无人值守、版本和部署边界；
- 对其他宿主只能作为独立兼容门，不得自动外推。

### 7.2 独立语义 PPTX 引擎

- 若能直接生成 P0 对象并通过目标宿主重开，可进入主候选；
- SDK 自己的 PDF/PNG 渲染不能替代目标宿主编辑和重开；
- fallback、未知保留和 workbook 关系必须分别验证。

### 7.3 模板优先

- 可以降低 P3 模板和品牌风险；
- 不能替代 P0 对象和关系证据；
- 适合作为所有主作者形态的组合策略。

### 7.4 语义中间层

- 应把 P0 对象和 P2 中文契约作为中间模型的硬字段；
- 不得设计一个假装所有作者引擎都支持 workbook/notes/preservation 的万能接口；
- 作者适配器必须声明自己的支持子集和退出条件。

## 8. 下一步的唯一允许动作

在不写实现代码的前提下，下一步只允许做一件事：

> **为首期代表性页面和图表类型建立 P0/P2 支持子集，明确每条候选路线在哪一项退出。**

不再扩展无关宿主、格式或候选名单。

## 9. 吸收分类

| 对象/机制 | 吸收分类 | 边界 |
| --- | --- | --- |
| A1-A9 原生对象判据 | **可直接复用** | 作为路线硬门，不因工程便利放宽 |
| B1-B5 中文排版判据 | **可直接复用** | 补充字体、AutoFit 和宿主渲染字段 |
| D1-D3 未知部件/局部编辑 | **适合二开** | 首期不作整稿主作者的硬门，但必须隔离记录 |
| 官方 API/功能声明与项目实测分层 | **可直接复用** | 禁止把供应商声明写成项目通过 |
| 目标宿主保存重开 | **可直接复用** | 作为 P0 的必要证据 |
| “看起来一样”替代原生对象 | **应当淘汰** | 不能替代图表、表格、文本和工作簿语义 |
| 无边界自动缩小字体 | **应当淘汰** | 中文零溢出不能靠静默牺牲可读性 |

## 10. 当前结论

> **路线比较现在有了退出条件：P0 原生语义和 P2 中文真文本是硬门；P3 模板、P4 审计和 P5 部署用于在硬门通过后排序；D 类未知部件保留可以首期隔离，但不能掩盖 P0 失败。**

本文件不选择 PowerPoint、商业 SDK 或 WPS，也不授权实现。
