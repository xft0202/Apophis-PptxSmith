## 1. 不可逆决策与可替换决策

### 第一日必须冻结的合同

| 合同 | 第一日要求 | 禁止路径 |
| --- | --- | --- |
| 关系事实库 | PostgreSQL 类长期关系库；事务、权限、备份、恢复和迁移纳入支持矩阵 | SQLite fallback、开发/演示/生产切换 SQLite、以后迁移 |
| BlobStore | S3-compatible 对象合同，版本、校验、保留、下载、临时 URL 和备份恢复可测试 | 生产长期文件目录、worker 本地目录作为事实源 |
| 工作流 | 可持久化历史、人工等待、取消、重试、幂等、恢复、版本策略和事件补偿 | 仅进程内任务、内存队列、Web 请求生命周期任务 |
| 身份 | 管理员/成员/审阅者、项目隔离、密钥隔离、审计和恢复；OIDC/企业 IdP 有边界 | 默认管理员、共享密钥、只靠前端隐藏按钮 |
| PPTX 事实源 | 原始 OPC 包和版本对象保留；只改授权部件；审计可追溯 | 整稿重建静默丢失未知部件/关系/备注/嵌入对象 |
| Provider | capability registry、超时、成本、数据路由、结构化输出/工具能力探测 | 把某个 OpenAI-compatible endpoint 当作语义兼容 |
| 交付 | A/B/C/D、中文量字、关系闭包、来源、PowerPoint/WPS 抽检和审计报告 | 只依赖浏览器/LibreOffice 预览或“生成完成”状态 |

### 可以延后决定但必须保持契约的实现

- 前端 React/Vue/Svelte；必须复用同一 API、事件和领域对象协议；
- Temporal/Restate/Hatchet/Camunda 等 durable runtime；必须实现同一 workflow fixture；
- SeaweedFS/Ceph/外部 S3 等对象实现；应用只依赖 S3-compatible contract；
- Keycloak/Ory/应用内身份/企业 OIDC；权限语义和审计字段不能随实现消失；
- LiteLLM/Bifrost/Higress/Portkey/直接 adapter；provider capability schema 不随网关绑定；
- Docling/MinerU/Unstructured/Tika 等解析器；统一输出材料事实、定位、来源和错误协议。

### 工作流结论

不能把“有重试”当作 durable execution。统一 fixture 必须包含：四道门暂停/恢复、人工确认、worker kill、provider timeout、重复提交、取消、版本升级、备份恢复、事件补偿和审计一致性。只通过 README 的候选不得进入主线。

## 4. 身份、模型网关与前端

### 身份

- **Keycloak**：官方文档覆盖 OIDC、SAML、LDAP、用户联邦和 RBAC；Apache-2.0 快照信号清晰，但 Java/运行组件较重。可作为企业 profile 或外部 IdP，不应把默认内置简单化成无审计账号。
- **Ory Kratos/Hydra**：官方资料显示 headless identity/OIDC/OAuth 分层，适合 API-first；组件分离、配置和用户体验实现成本需要 Spike。
- **ZITADEL**：能力和企业协议值得参考；AGPL 边界不进入 MIT 核心默认，可作为外部服务。
- **Authentik**：协议支持和自托管 UX 值得调查；许可证、版本支持、备份升级和社区风险必须锁定，未完成前只作外部候选。
- **应用内身份**：并非“没有 IdP 就简单”。若提供本地账号，必须第一天实现密码/MFA/恢复/session/CSRF/项目隔离/密钥审计，并提供 OIDC 接入边界。

### 模型网关

- **直接 provider adapters**：最容易保留数据路由和业务语义；必须有 capability registry、provider contract test、超时、预算、fallback 和密钥边界。
- **LiteLLM**：官方/源码展示多 provider、routing、fallback、预算、virtual key 和 observability 经验；版本许可证、结构化输出和图像/工具/embedding 语义需本项目实测。
- **Bifrost**：GitHub 快照显示 Go/Apache-2.0 方向，提供统一 provider/gateway 经验；性能和兼容性声明不能替代 contract test。
- **Kong/Higress/Envoy AI Gateway**：企业网关、插件、限流、AI proxy 和治理强；Higress 官方资料具体展示 Wasm plugin、token rate limit 和 AI statistics。Envoy 方向需区分官方 AI Gateway 站点与 Kubernetes Gateway API Inference Extension；本轮 `envoyproxy/ai-gateway` API 路径出现非预期重定向，不能据此确认仓库许可证/维护状态。K8s/Envoy 运维边界不适合无条件下沉到默认单节点。
- **Portkey Gateway**：官方资料覆盖多模型路由、retry、fallback、guardrail 和 observability；self-host/许可证/企业功能分界按版本核验。

### 前端与工作台

- **SANDUN**：透明流水线、阶段产物、便利贴大纲、项目/风格连续性和逐页上下文，作为 UX 基准；SVG 级编辑、黑盒置信度、画布负担、积分墙不采用。
- **Gamma**：官方资料证明 Generate/Paste/Import、AI edit、手工编辑和撤销；吸收低摩擦预览/回滚，不接受其内容密度或目标软件边界作为本项目质量。
- **Plus AI**：官方指南证明 outline、Rewrite/Remix、PowerPoint/Slides 宿主交付；吸收动作拆分和结构确认，不依赖商业插件。
- **Gemini in Slides**：官方帮助证明澄清、sources/steps 计划、批准、逐页预览/插入/替换；吸收计划可见性和来源链路，不把 Google 宿主当自托管基座。
- **React/Vite、Vue/Nuxt、SvelteKit**：都保持候选；必须以相同事件协议、中文 IME、阶段门、可访问性、1440px 信息密度和未来客户端复用 fixture 比较，不由样本产品反向锁定框架。
- **LibreChat/Open WebUI**：可借鉴 provider、文件、流式事件、群组权限和工作台信息架构；不复制整个服务/许可证/模型边界。
- **PPTist**：schema、撤销/重做、编辑器细节可借鉴；AGPL 和其 PPTX 保真边界禁止直接集成。
- **Presenton/PPT Master**：自托管/BYOK、原生 PPTX、确定性转换、postflight 经验可借鉴；所有“可编辑”声明必须本项目实测。
- **Flowise**：调查快照显示已归档，历史 UI 经验不进入长期基线。

## 5. 材料解析、PPTX 和渲染

- **Docling/MinerU/Unstructured/Tika**：分别提供文档解析/版面/表格/通用内容能力；必须比较中文、来源定位、许可证、模型/外部依赖、崩溃恢复和材料事实，不允许直接成为事实源。
- **ONLYOFFICE**：可作为 Office 渲染/编辑和私有化平台的企业参考，但社区版许可证、商业版边界、服务拓扑和目标软件等价性必须独立审查；不能把它当作免费 PowerPoint/WPS 验收替代。
- **PDFium/Skia/HarfBuzz**：可分别提供 PDF/图形栅格/文字 shaping 能力；它们是渲染和几何工具，不是完整 Office 语义引擎。

## 6. 三套长期组合的证据判断

### A：控制面 + durable runtime + 专用编译流水线

- Web：独立 PC Web 工作台；API：typed REST + 可恢复事件；
- Workflow：Temporal/Restate/Hatchet 统一 fixture 后择一；
- Data：PostgreSQL 事实库 + S3-compatible BlobStore；
- Workers：解析、内容/provider、PPTX 编译、预览/QA、PowerPoint/WPS gate；
- Identity：本地长期身份边界 + OIDC/企业 IdP 接入；
- Observability：OpenTelemetry、结构化审计、SBOM、签名、备份/恢复；
- Release：单节点 Compose 运行同一生产组件，扩容加副本或外部服务，不更换地基。

判断：最符合四道门和 PPTX 质量目标，作为形态首选；具体 vendor 未冻结。

### B：事件原生 + NATS/JetStream + Restate/Hatchet

- Web/API 同 A；事件主干负责 command/event；durable service 负责 keyed state、promise、retry 和 workflow；PostgreSQL 保存投影/事实，S3 保存对象；
- 优点：重放、集成、跨 worker 和故障观察强；
- 风险：schema、重复投递、投影一致性和单节点运维更复杂。

判断：长期平台候选；必须完成单节点、备份、恢复和贡献者理解 Spike。

### C：Camunda/Argo + Keycloak + Ceph/OpenSearch 企业平台

- Web/API + enterprise IdP；Camunda/Argo 负责流程或容器任务；PostgreSQL/CockroachDB + Ceph/S3 + OpenSearch；OTel + GitOps/Helm；
- 优点：企业人工任务、平台治理、artifact、审计和扩展强；
- 风险：Kubernetes/Ceph/搜索/流程引擎地基明显重于当前单节点支持范围，许可证和升级面更广。

判断：企业部署参考/隔离 profile，不作为默认。

## 7. 下一轮实证矩阵

1. Workflow fixture：四道门、人工等待、取消、provider timeout、重复提交、worker kill、版本升级、恢复、审计一致性。
2. Storage fixture：PostgreSQL 备份恢复、S3 版本/校验/临时 URL/删除恢复，至少两个 S3-compatible 实现；不使用 SQLite 或生产本地目录对照。
3. Identity fixture：管理员/成员/审阅者、跨项目访问、provider key、注销/恢复、OIDC、审计、备份恢复。
4. Gateway fixture：结构化输出、工具调用、图像、生图、embedding、限流、预算、fallback、provider 故障和敏感数据路由。
5. UX fixture：SANDUN、Gamma、Plus AI、Gemini 的澄清/计划/大纲/预览/修改/回滚动作，与 1440px、中文 IME、SSE 断线补偿和审计联动。
6. PPTX fixture：原生图表/表格/嵌入工作簿、中文长标题、未知部件/关系、notes、master/layout/theme、目标软件保存重开。

## 9. 当前结论

- 已可确定长期架构形态：**控制面 + durable workflow + 专用解析/编译/QA workers + PostgreSQL 事实库 + S3-compatible 对象合同 + 长期身份/审计/观测边界**。
- 尚不能确定具体 workflow runtime、前端框架、对象存储实现、身份产品、模型网关和 parser；这些必须通过统一夹具而非偏好决定。
- SQLite、本地生产文件、进程内任务、未经验证 provider、AGPL/不透明依赖和 Flowise 归档路线不得进入支持基线。
- SANDUN 是体验基准，不是技术锚点；最终产品必须把它的流程优势与 A 级 PPTX、中文质量、证据审计、回滚和自托管组合起来。
- 票 21 关闭前不创建生产脚手架、不更新技术终决 ADR、不恢复 14–20 的旧答案。
