# SANDUN 全量解剖与反超清单

- 调查日期：2026-09-25
- 调查方法：**官方文档站全量抓取（28/29 页成功，唯一失败页 `/docs` 本身返回 404）+ 首页与 pricing 页实测 + 首轮调研的四份回放实测记录交叉印证**
- 证据级别：**官方声称**（其自家文档/产品页）与**本项目实测**（抓取到的页面结构、限制条数、流程卡点数）两类，逐条标注
- 抓取产物：`research/experiments/sandun-raw/`（28 个 RSC 载荷文件，可复查）
- **重要边界**：本文档只解剖 SANDUN。它仍然是**体验基准**，不是技术采用对象。其 SVG 路线与托管锁定不进入本项目。

---

## 1. 一句话结论

SANDUN 的**流程编排已经做到同类产品里最细的一档**——六阶段、每阶段有人工卡点、每页有版本留痕、图表有独立可编辑槽位、风格能沉淀复用。它的护城河是**设计 know-how 的持续打磨**，不是单点技术。

它真正没解决的是**交付可信度**：SVG 是形状级可编辑（不是语义级）、字体要用户自己装否则错位、联网检索的"置信度"是黑盒数字、材料解析有 6000 字上限、没有交付审计。**这四条正是 PptxSmith 的立身之处。**

## 2. 完整六阶段流水线（实测复原）

其文档站 `workflow/` 下六个页面构成的主干。**注意：是六阶段，不是我此前记录的"四道门"。**

```text
① 背景调研 + 内容需求单（澄清）
      ├─ 固定三问：页数档位 / 内容类型 / 视觉素材偏好
      ├─ AI 再生成 3 道贴合主题的追问
      └─ 自由补充栏；30 秒未操作自动提交默认值
② 大纲门（便利贴画布）
      ├─ 双击改标题与要点
      ├─ 增删页面；调整章节结构
      └─ 约束：封面/目录/结束页不可删；每章至少留 1 页
③ 联网深度搜索
      ├─ 先列「搜索清单」，每条对应大纲的具体内容点
      ├─ 逐条联网检索，画布实时展示每页搜索进度与结果卡片
      ├─ 结果卡片可点开看提炼要点与原始来源链接
      └─ 上传 PDF 且选「仅使用 PDF 材料」→ 跳过联网
④ 内容策划（逐页文案定稿）
      ├─ 按页组织文案要点与素材安排，与大纲一一对应
      └─ 官方明说：此时改文字成本最低，进设计稿后再改要连带调版式
⑤ 初稿（内容完整、设计从简）
      ├─ 文案、数据、结构就位；视觉留到下一阶段
      └─ 单页可「重新生成此页初稿」
⑥ 风格选择（流程停下等确认）
      ├─ AI 推荐 3 套截然不同的风格
      ├─ 可展开完整设计规范：色彩/字体/圆角/间距/描边/阴影 + 卡片样例
      ├─ 规范详情支持「复制 JSON」与「保存到风格库」
      └─ 第 4 张卡是自定义：文字描述或传参考图（≤5MB）
⑦ 正式设计（选生成方式，再批量产出）
      ├─ SVG 矢量 或 GPT Image 2
      └─ Image 2 先出 1 页样张确认，再批量
```

**阶段门数量 = 7 个卡点**（需求单、大纲、搜索清单、策划、初稿、风格、生成方式）。这比我此前的"四道门"更细。**其设计哲学值得完整吸收：每一阶段停下，且每阶段的返工成本都被明确告知用户。**

## 3. 两种渲染模式（核心架构事实）

| | **SVG 模式** | **Image 2 模式** |
| --- | --- | --- |
| 产物本质 | 矢量结构，每元素独立 | 整页位图 |
| 可编辑性 | 文字/图片/图表/图层都能拖拽缩放改样式 | 只能自然语言重绘整页 |
| 修改路径 | 画布内直接编辑 + 自然语言 | 仅自然语言重绘；或"解析导出" |
| 导出格式 | SVG / PNG / PDF / PPTX | PNG / PDF / 图片 PPTX / 可编辑 PPTX（需元素解析） |
| 生成耗时（官方） | 约 3–5 分钟 | 约 5–10 分钟 |
| 生成开销 | 低 | 高（官方："消耗较多时间"） |
| 适用 | 迭代型（周报、提案） | 终稿型（发布会、路演） |

**关键事实**：Image 2 是**位图**。它的"可编辑 PPTX"是**事后 OCR/元素解析**出来的——官方原话是把图片页"解析为可编辑的文字与元素"。这是**逆向重建，不是原生语义**，必然丢保真度。

**`design/render-modes` 页原话**（官方声称）：
- SVG 模式："画布内完全可编辑：文字、图片、图表、图层"，以及"导出可编辑 PPTX 后解析编辑"
- Image 2 模式："页面整体重绘，细节由 AI 把控"

**PptxSmith 的攻击点**：两种模式都是**B 级或更低**。SVG 改不了图表数值语义（SVG 不携带数据源），Image 2 更是位图。**我们要做的是 A 级：图表带嵌入工作簿、表格可增行、改数值图表实时更新**——Spike C1 已实测通过。

## 4. 编辑器能力（实测清单）

SANDUN 的 SVG 页面编辑器相当完整，**这是它投入最大的地方**：

| 能力 | 细节 |
| --- | --- |
| 页面编辑 | 双击改文字；拖拽/缩放/旋转；组合与多选；完整快捷键表 |
| 参数面板 | 选中元素后下方出现面板，快速调节属性 |
| 图层面板 | 图层列表 ↔ 画布双向选中；显隐、锁定、置顶置底、组合、右键菜单 |
| 图片编辑 | 4 种换图来源：本地上传 / 最近使用 / **可商用图库搜索** / AI 生成 |
| 图表编辑 | 独立的"编辑图表数据"接口：直接改数据项与数值，图表**实时刷新**；可调系列/数据项配色 |
| 布局修复 | SVG 页有"修复"按钮；可"还原"；还有"深度修复"（AI 基于截图重排版） |
| 版本历史 | **按页独立**记录；来源标签区分（对话修改 / AI 布局修复 / 手动修改 / 回退操作）；可预览快照、一键回退、删除；回退本身也生成新记录 |
| 撤回 | 三层：编辑器 Ctrl+Z、对话面板"撤回上次"、版本历史回退 |
| 单页重生成 | 缩略图悬停 → 重新生成此页初稿/设计稿，不影响其他页 |
| 批量重试 | 失败页单独重试；多页失败"全部重试" |
| 视图 | 三视图切换（搜索/大纲、初稿、设计稿），美化项目多一个"原稿"只读视图 |

**注意图表编辑这一条**：它在**画布内**改图表数据并实时刷新——这说明它的图表是 SVG 里的一套自绘结构，**不是 OOXML 的原生 chart part**。导出成 PPTX 后，这个图表在 PowerPoint/WPS 里**能否继续改数据**，官方文档没有承诺。这正是我们的验证重点。

## 5. 风格系统（值得整体吸收）

比我们此前理解的更成熟：

1. **系统风格库**：上百套内置风格，分四个分类，悬停预览，点击直接套用（"无需等待 AI 重新构思"）。
2. **用户风格库**：解决"每次都要重新调风格"——
   - 上传一张 UI 截图/设计稿/PPT 页面（JPG/PNG ≤5MB）+ 可选文字描述；
   - AI 解析生成**完整风格规范**（配色、字体、结构、图表配色）；
   - 在可视化编辑器里微调各项参数；
   - 之后所有项目直接复用；
   - 支持编辑与删除；
   - 官方提示：团队有固定 VI 时做成一条用户风格，之后一键对齐品牌形象。
3. **风格规范的结构化程度高**：色彩（主题模式、页面底色、渐变、强调色、卡片填充、主/次文字）、字体（页面标题、卡片标题、正文、注释）、几何（圆角、间距、内边距、描边、阴影）。
4. **规范可导出**：「复制 JSON」——这实际是一个**可移植的风格包协议**。

**与 ADR-0005（引擎与风格包解耦）对照**：SANDUN 已实现"引擎与风格包解耦"，且风格包是一个可读的规范结构，还能从参考截图**自动提取**。这比我此前设计的"风格包"更完整。**必须吸收，并补强两点**：①从既有 **PPTX** 直接提取风格包（它只能从图片提取）；②风格包必须可与引擎解耦导出为开放格式。

## 6. 输入通道（实测三入口 + 美化）

| 通道 | 支持格式 | 限制（官方） |
| --- | --- | --- |
| 一句话生成 | 文本 | 超 500 字自动转存为需求文档，上限 6000 字 |
| 需求文档 | docx / txt / md | **单文件 ≤50MB，可多选；解析上限 6000 字**，超出需拆分 |
| 参考资料 | PDF | 单文件 ≤50MB，可多选，**不限字数** |
| PPT 美化 | ppt / pptx | 单文件 ≤100MB，单次一个 |
| 风格参考图 | PNG / JPG | ≤5MB |

**两个真实限制值得注意**：

1. **需求文档 6000 字硬上限**——"文本解析上限为 6000 字，请拆分成多个文档一起上传"。这是它自己文档里承认的能力边界。**PDF 通道不限字数**，所以官方建议长材料转 PDF。这暴露它的 docx/txt/md 解析是新写的且很浅。
2. **需求文档不支持 PDF、不支持旧版 .doc**——PDF 只能走"参考资料"通道（语义不同：参考=写什么，需求=怎么写）。

**需求文档的设计思想值得学**：逐页写"内容 + 布局参考"（如"2×2 网格卡片"、"左右双栏"、"三列等宽卡片"）。**写了布局建议 AI 就尽量遵循，不写则自行设计**。它甚至给了"文档内容 vs 成品页面"的真实对比大图。这是**把版式控制权交给会用的人**的好设计。

**双通道分工也很清晰**：
- 需求文档 = 负责"**怎么写**"（结构、版式、行文）；
- 参考资料 PDF = 负责"**写什么**"（事实素材与数据来源）；
- 同时上传时，按需求文档的组织框架 + 从 PDF 取素材填充。

## 7. 回放分享（被低估的体验设计）

- 每个项目的生成过程**完整记录**；
- 开启共享后，链接**任何人无需登录即可只读回看**——像看录像一样复现各阶段画面（大纲、搜索、初稿、设计稿），消息流与流程卡片同步推进；
- 访问者全程只读：不能编辑、不能导出、不能发消息；但可自由切换视图、聚焦页面看细节、继续转发链接；
- 关闭开关链接即刻失效；
- 官方列的三类用途：让客户/上级看到"这份 PPT 是怎么来的"、同事定位到某步提修改意见、首页的"生成案例"就用回放链接呈现。

**这一条对我们的启示很大**：它把"过程透明"从产品内延伸到了**对外协作场景**——汇报时领导问"这页数据哪来的"，可以直接甩一条只读回放链接。**PptxSmith 应该做类似的事，但用审计报告而非回放录像**：回放是录像，审计报告是可核验证据。甚至可以做"回放 + 审计"双轨。

## 8. 其自认的边界（对我们最有价值的一节）

这些是**它自己文档里写明的限制**，全部是官方声称：

| 限制 | 原文/依据 | 对我们的意义 |
| --- | --- | --- |
| **字体必须用户自己装** | 导出后"下载卡片附有『安装字体』链接"，"演示前请先在目标电脑安装字体，避免版式因缺字体而错位" | 用 HarmonyOS Sans（无版权可商用）。**它选了安全字体，但把安装责任推给了用户**。我们的量字烘焙+溢出审计是正面解 |
| **SVG 导出后改不了 | 需"导出可编辑 PPTX 后解析编辑" | 形状级≠语义级 |
| **Image 2 是位图** | "页面为整图，没有图层结构"，无图片/图表槽位 | 交付可信度低 |
| **需求文档 6000 字上限** | FAQ 明写 | 解析能力浅 |
| **美化模式不支持自然语言编辑** | "已有 PPT 美化模式暂不支持自然语言编辑" | 旧稿路径不完整（我们首期也不做） |
| **"撤回上次"会失效** | "再次编辑或流程推进到下一阶段后，『撤回上次』失效" | 版本控制不彻底 |
| **美化不可新增页** | "可编辑、可删页，但不可新增页面" | 结构锁定 |
| **图表数据在画布内改，导出后未承诺** | 文档只讲画布内编辑，未讲 PPTX 中可改 | **这正是 A 级验证的关键空白** |
| 手机端只能看 | "手机端适合查看项目与回放" | 与我们的 PC-only 定位一致 |

## 8.5 四份官方案例封面的视觉实测（2026-09-25，本项目实测）

抓取首页「生成案例」四张封面原图（`research/experiments/sandun-raw/covers/`），逐张目检：

| 案例 | 题材 | 底色 | 主色 | 特征 |
| --- | --- | --- | --- | --- |
| 北京五日深度游攻略 | 生活/旅游 | 米白暖底 + 淡红水印数字 | 砖红 `#B03A2E` 系 | 红色胶囊标签，右下超大年份水印 |
| 正泰电器企业介绍 | 企业介绍 | 极浅薄荷绿渐变 | 深墨绿 | **使用正泰品牌绿**，右上同心圆装饰线，底部绿色斜角带 |
| Dify 产品技术架构 | 技术路演 | 深蓝紫渐变 + 星点 | 亮蓝紫 | 深色科技感，右上节点连线装饰 |
| 小米 2025Q3 业绩 | 财务报告 | 浅灰网格纹理 | 亮橙 | **使用小米品牌橙**，底部 2 张数据结论卡 |

### 修正此前结论

首轮调研记录「三份成稿主色族均为 Tailwind slate 灰阶 + `#2563EB` 蓝 + 浅底——三个题材视觉风格高度相似」。**本次实测不支持这个结论**：四份封面的配色差异明显，其中两份还准确贴合了对应品牌的 VI（正泰绿、小米橙）。

### 真正一致的，是版式骨架（这才是问题所在）

四张封面的**布局结构高度同构**：

```text
[品牌/标签元素]           ← 左上
（留白）
│ 巨型标题                ← 左侧，配一条装饰竖线
│ 副标题
（装饰图形）               ← 右侧
─────────
底部信息位 ×2–3            ← 左下分区
```

**这是比"配色单一"更准确、也更值得重视的结论**：SANDUN 的**配色可变（而且能认品牌），但版式原型基本固定**。所以我们的风格包不能只包含颜色令牌，**必须把版式原型（layout archetypes）也纳入风格包**——否则换色不换骨，用户拿到的仍是同一张脸。这一条要写进 ADR-0005。

## 9. 反超清单（逐条可验证）

按"它没解决 + 我们能解决"排列，**每条都对应本项目已实测的能力**：

| # | SANDUN 的现状 | PptxSmith 的反超 | 验证方式 |
| --- | --- | --- | --- |
| 1 | SVG 形状级 / 位图，图表导出后语义不明 | **A 级原生语义**：图表带嵌入工作簿、表格可增行、改数值图表更新 | Spike C1 已实测通过；需在 WPS/真 PowerPoint 双目标复验 |
| 2 | 字体要用户自己装，否则错位 | **中文量字烘焙 + 溢出审计**，出厂即定版式，换机不走样 | Spike B 已实测折行；需补安全余量与双目标校准 |
| 3 | "置信度"是黑盒数字 | **可核验证据链**：逐事实来源 + locator + 冲突标记 | fixture 的 15.0/15.1 冲突已就绪 |
| 4 | 无交付审计 | **审计报告**：对象清单、可编辑等级、来源核验、溢出检查、成本、验证环境 | 需定义（票 08） |
| 5 | 需求文档 6000 字上限、格式窄 | 不设人为低上限；**中文 docx/xlsx/pptx 原生解析** | 需 parser 选型 |
| 6 | 托管闭源，材料必须出境 | **MIT 开源 + 自托管 + BYOK**，材料不出部署环境 | ADR-0001/0002/0004 |
| 7 | 风格库只能从图片提取 | 风格包**可从既有 PPTX 提取** + 开放格式 | 需验证 |
| 8 | **版式骨架**高度一致（四份不同题材案例的封面，布局骨架相同：左侧标题块 + 装饰竖线 + 副标题 + 底部 3 个信息位） | 风格包体系 + 工程规则引擎分层保证；**版式原型也应进入风格包**，而非固定在引擎里 | ADR-0005（需扩写） |
| 9 | 回放是"录像"（看得到过程，验不了结论） | **回放 + 审计双轨**：过程可见，结论可验 | 需设计（票 07/08） |

**必须承认它领先、我们要追赶的部分**：

- **阶段门更细**（7 个卡点 vs 我们的 4 道门）——建议重新评估是否要增加"搜索清单确认"与"风格选择"两个独立卡点；
- **编辑器成熟度**——图层、组合、快捷键、布局修复、深度修复，这些是大量工程积累。我们首期不做画布编辑器（ADR-0008），但要**在"对话式修改 + 大纲面板直改 + 预览回滚"这条路线上做到同等可信**；
- **风格库的即时套用体验**——"点击即用，无需等待 AI 重新构思"是个很强的体验点；
- **推荐 3 套截然不同风格**的能力；
- **单页独立版本历史**比整稿版本更细，值得考虑。

## 9.5 吸收分类（博采众长原则的强制字段）

按地图 Notes 的强制要求，对 SANDUN 做**分层判定**——不得用一句话概括整个项目。
同一外部样本各层结论不同，必须分开落位。

| 层 | 吸收分类 | 具体取/弃 | 理由（证据级别） |
| --- | --- | --- | --- |

| **托管 / 账号 / 商业机制** | **应当淘汰** | 弃：与 MIT 开源、自托管、BYOK 定位冲突 | ADR-0001/0002/0004 |

### 一句话总结分层结论

**取**：它的**流程编排与信息组织**（四个可借鉴层：交互节奏、阶段产物、风格系统、逐页来源）。
**弃**：它的**导出与字体实现**（三个应当淘汰层，均有本项目实测支撑）。

**关键边界**：所有「仅可借鉴」项**一律不进依赖树**——
本项目不从 SANDUN 引入任何代码或资源。

## 10. 对现有决策的直接影响（待确认）

以下三条是本次解剖暴露的**决策缺口**，需要进入地图：

1. **阶段门是否需要从 4 道扩到 6–7 道？** ADR-0008 定的四道门（澄清→大纲→代表页→交付），但 SANDUN 实际有 7 个卡点：需求单、大纲、**搜索清单**、**内容策划**、初稿、**风格选择**、生成方式。其中"内容策划（逐页文案定稿）"和"风格选择"是两个高价值卡点，**我们的四道门里没有**。这是需要重新评审 ADR-0008 的实质问题。
2. **风格包协议是否以 SANDUN 的规范结构为参照？** 它的规范字段（色彩 6 类、字体 4 级、几何 5 项）已经是一份可用的结构；它还支持「复制 JSON」。我们可以参照并加上"从 PPTX 提取"。
3. **"过程透明"的产品形态：回放 vs 审计报告？** SANDUN 选了录像式回放（可对外分享、看得到过程）。我们原计划是审计报告（可核验结论）。**两者不互斥，且组合起来才是完整体**——建议两者都做。


复现方式：抓取 `https://sandun.cc/docs/<path>`，用正则 `self\.__next_f\.push\(\[1,"..."\]\)` 提取 Next.js RSC 载荷并拼接，再按 JSON 字符串还原。注意其 `/docs` 本身 404，但 `/docs/<path>` 全部可用；`robots.txt` 只禁止 `/api/`、`/generate`、`/oauth-popup`、`/docs-editor`，文档站是公开的。

### 回放数据端点的实测结果

从 JS chunk 中提取到其 API 全貌（`/api/agent/{start,message,pause,resume,stop,sync-outline}`、`/api/styles/user-presets/generate`、`/api/ai/generate-style-recommendations` 等），并在代码中找到回放端点：

```text
${window.location.origin}/replay/${e}
/api/replay/${encodeURIComponent(e)}
sandunppt:replay:${e}     ← localStorage 缓存键
```

**实测**：`/api/replay/{id}` 匿名访问返回 404，说明该端点需要登录态或需要对应项目已开启共享。因此**公开态下无法直接取回放数据**。

另外，`robots.txt` 明确禁止抓取 `/api/`、`/generate`、`/oauth-popup`、`/docs-editor`——故不继续探测其 API 行为。

**未做**：登录态内的实测（需账号）、导出 PPTX 的实际产物验证、生成过程的真实耗时实测。这些留待后续——尤其是**导出的 PPTX 在 WPS 里的图表可编辑性**，这是验证第 1 条反超的关键，但需要注册账号生成一份真实产物。
