## 一、新增关键事实

### 1. 竞争格局已变：Kimi K3 把旧判断推翻了

旧报告引用的是 Kimi 早期"PPT 助手"（实为 AiPPT 联合版）。2026-09-18 更新的官方指南显示，Kimi PPT 已由 K3 驱动重做：**官方**声称——

- 上传 pptx 可作为模板或**直接修改编辑**；
- 内置在线编辑器（文本/形状/图表数据可改），支持批注 + 多轮对话续改；
- 自动构建主题样式（主题色/文本样式统一改）；
- 支持动画（含交互动效）；
- 导出 ppt 可选**嵌入字体与切换动画**，声称"元素样式、页面布局、图表动画均与 Kimi 中展示一致"。

> 影响：01 报告"竞品过程拆解"和 02 报告"商业差异"中关于 Kimi 的描述已过时。本项目与 Kimi 的能力重叠面显著扩大。Kimi 未公开、且第三方未验证的点：**上传旧稿修改时是否原包级保留（母版/备注/嵌入对象/未触及区域零变化）**、**导出 PPTX 中原生图表占比**、**长文中文排版的溢出率**。这三点仍是差异化候选空间，但必须以同题测试证实，不能假设成立。

### 2. 中文排版痛点有独立第三方实证，不是假设

- WPS AI 生成的 PPT 跨设备乱码：默认使用未预装字体（霞鹜文楷、阿里巴巴普惠体等）且未嵌字体，目标机替换后"方块/乱码/布局错乱"。（**第三方实测/GitHub、CSDN 问答**）
- Gamma 中文实测：出现过把"锂电池"翻成英文混入中文段落；PPTX 导出字体映射偶发崩溃，需在 PowerPoint 重新指定中文字体。（**第三方实测**）
- Beautiful.ai 中文实测：标点混用，中文支持是其明确短板。（**第三方实测**）
- 横评共识（6 款/4 款两轮独立评测）：**所有工具都存在数据准确性或逻辑瑕疵，需要人工二次核验**；"生成完不用大改"没有产品做到。即触 AI PPT 以"保持原文"模式为卖点，声称测试中 32 个数据点零改写。（**第三方实测**，单来源）

> 影响：01/02 报告中"中文排版"与"事实保真"两个痛点方向被独立证据强化；"事实零改写"已经有竞品在主打，我们的 R02（事实与来源）需要做到可审计而不只是不编造。

### 3. 中文量字引擎已有 MIT 开源实现，不必自研

cjk-pptx-engine（**官方 README + 源码**，MIT，Python 3.9+）：

- 根因诊断与 01 报告一致：python-pptx 不做文字度量，"中文字≈1em"估算误差可达 14%；
- 解法：读真实字体文件逐字量宽 + lineGap 精确行高 → 折行预测 → fit_size 自动缩字；已按 PowerPoint 实际渲染校准（微软雅黑 1.34×、宋/黑/楷/仿宋 1.16×、等线 1.05×，等线 +5% 偏差）；
- 交付闸门 `cjk-audit`：越界/溢出/字体替换/几何重叠检测 + 美学 lint，松集成模式可审计**任何工具**生成的 PPTX。

> 影响：03 报告技术选型表应新增该依赖（直接复用，MIT）。它同时验证了"数学测量 + 审计闸门"路线的可行性——这条路不花 token、数据不出境。代价：它是 Python 生态（python-pptx），与 03 报告的 PptxGenJS(TS) 编译线有语言边界，需要决定"测量在 Python、生成在 TS"的跨语言集成，或"文本密集页用 Python 生成"。

### 4. Anthropic 官方 pptx skill 的过程证据（重要方法论来源）

研读其 SKILL.md 全文（仓库注明 **Proprietary 许可**，只能借鉴思想，不能复制文本）：

| 其做法 | 对我们报告的意义 |
| --- | --- |

### 5. 旧稿样本最小实验（本项目 input/例子.pptx）

解包实测：4 页、2 母版、24 版式、**1 个原生图表（含嵌入 Workbook1.xlsx + chartStyle/colors/themeOverride 四个关系部件）**、10 张 PNG、无动画、主题字体等线。

> 影响：样本构成了"修改图表数据需同步嵌入工作簿与缓存"的真实最小用例（03 报告表中"图表与表格"行的落地验证对象）。但样本无动画/无 SmartArt/无 OLE/无组合对象，不能代表旧稿难度上限；首批 12 份旧稿样本仍需按 01 报告第六章收集。

### 6. 架构参照：Presenton

Presenton（**官方**，Apache 2.0）：FastAPI + Next.js/Electron，模板即 JSON 布局、自定义模板、自托管为卖点（"No SaaS lock-in"）。国产 SlideForge/PaperJSX 等则以 API 计费（$0.05/页级）切入。

> 影响：验证了"本地/私有化 + 自带模型"是一条被表达出来的市场需求（尤其企业敏感材料，呼应 02 报告"敏感材料处理"风险行）。其前端拖拽编辑器投入巨大，我们首期不应复制。

## 四、识别到的冲突与张力（必须先解决）

1. **AGENTS参考资料的设计教条 vs 市场设计多样性**：该文件强制"纯浅色 + Bento 网格 + 16:9 + 微软雅黑/思源黑"。但 Gamma 的领先点在内容驱动的多样调色板，Anthropic skill 也明确"不要默认蓝/acccent 条/千篇一律版式"。**Bento+浅色本身正在成为"AI 味"的特征**。品牌合规场景下，教条会让位于客户 VI。→ 需要把该文件降级为"默认风格基底之一"，还是维持为强制规范？（与 Q3 人群选择强相关）
2. **Java 21 编排 vs Python 生态资产**：03 报告选 Java 的理由是"组织现有服务栈"，但本问题域的关键资产（python-pptx、cjk-pptx-engine、markitdown、defusedxml、LO 脚本）都在 Python。双语言（Java 编排 + Python/TS 工作进程）对一个尚未验证需求的项目是三重复杂度。→ 与 Q1 联动。
3. **旧稿补丁是先做还是后做**：竞争最弱的地方（连 Kimi 都大概率是重建式修改），但技术最难、验收成本最高；新建链路短、能快速跑通价值闭环。→ Q2。
4. **自研在线编辑器是个坑**：Kimi/Gamma/Beautiful.ai 的核心壁垒之一是编辑器，投入以年计。我们首期若以"对话+审计交付"闭环验证价值，可以不建编辑器（导出后用户在自己 PowerPoint 里改——这本来就是目标人群的真实习惯）。

## 六、第二轮补充证据（语言栈可行性，2026-09-24）

针对"量字引擎在 Python、PptxGenJS 在 TS"语言边界问题，新查证：

1. **fontkit（foliojs，MIT）证明 TS 侧真字体测量可行**：支持读 glyph metrics、layout(文本) 得 advanceWidth，日文 Qiita/博客圈已有 CJK 实操（まさたか日記）。即 cjk-pptx-engine 的"读字体文件逐字量宽"方法**可移植到 TS**，不存在原理障碍。（官方文档 + 第三方实操）
2. **python-pptx 官方仓库维护停滞**：scanny/python-pptx 最后发布 1.0.2（2024-08），Snyk 标记 Inactive；**但存在活跃 fork**：MHoroszowski/python-pptx 于 2026-05-05 发布 1.2.0（新增 customXml 一等支持）。（包仓库+Snyk 健康数据）
3. **PptxGenJS 的 fit:'shrink' 依赖 PowerPoint 打开时的 normAutofit 重算，不是生成时烘焙**（issue #330/#779 报告行为不一致）；而新兴项目 ts-pptx（shbernal）专门做了"measured text fit"：用字体度量 + PowerPoint 校准 oracle 在生成时烘焙缩字结果。（issue + 项目文档）

> 结论：量字+烘焙缩字（而非依赖打开时自动缩字）正在成为程序化生成 PPTX 的最佳实践。cjk-pptx-engine 是其 Python 实现；TS 生态尚无等价物，但 fontkit + PowerPoint 校准 fixture 的路线已被两个独立项目验证。

**由此，主语言栈收敛为两个现实选项（双语言全栈被排除——研究阶段承担不起）：**

- **A. TS-first**：PptxGenJS 生成 + 自研 fontkit 量字（借鉴 cjk-pptx-engine 校准数据）+ cjk-audit 仅作独立验收 CLI。优点：图表生态最强、与 agent 工具链（skill 生态主流是 JS/TS）一致；代价：量字移植与校准要一次性投入。
- **B. Python-first**：python-pptx（MHoroszowski fork）+ 直接复用 cjk-pptx-engine 全链。优点：中文排版安全最快落地；代价：图表类型覆盖面较窄（约 6 类常规图）、长期绑在 fork 的维护节奏上。

（2026-09-24 更新：已定 A 的变体——TS 全栈 + 自研量字，见 ADR-0003。）

## 八、标杆产品 SANDUN（sandun.cc）解剖（2026-09-24，第三轮）

所有者明确产品形态对标 SANDUN 且"比它更好"。证据来源：其官网（Next.js 站点，创建于 2026-02）、创始人公开方法论文章（h.sjds.net/a/490290）、第三方产品页（watcha.cn）。

**其工作流**（官方+创始人自述）：需求调研（主动检索+追问）→ 大纲策划（"便利贴"模式，可拖拽增删调序）→ 策划稿（每页版式与信息架构先行）→ 设计稿（风格样式后置）→ 成品。有项目库、用户风格库、积分体系、旗舰/专家双档模型路由（专家档 3× 积分消耗）。创始人自述核心壁垒是把设计方法论（含 Bento Grid 便当网格）写成模型指令。

**关键事实：其"完全可编辑"是 SVG 路线**（官方产品页原话："最终产出的 PPT 完全可编辑（基于 SVG 格式）……直接导入 PPT 软件中进行任意编辑"）。SVG 不携带图表数据语义；在 PowerPoint 中 SVG 需"转换为形状"才能改外观，且**图表数值、表格行列不可作为数据编辑**。

> 这正是本项目可攻击的结构性缺陷：**SANDUN 的可编辑是 B 级（形状级），我们能做到 A 级（语义级）**。同时其编排思想（分阶段、便利贴大纲、策划先行、模型分档路由）与本项目 01/04 报告的过程设计高度同构，可直接借鉴并开源化。

**SANDUN 已做到、我们不能假设领先**：主动调研追问、拖拽大纲、策划/设计分离、风格库、资料检索填充、上传旧稿美化（Agent 模式）。
**SANDUN 未公开证明、我们的候选差异化**：①A 级原生语义输出（图表带嵌入工作簿、表格可增行）；②中文量字烘焙缩字（零溢出交付闸门）；③事实保真（零改写+来源可追）；④交付审计报告（对象清单+可编辑等级+验证状态）；⑤开源自托管（无积分墙、BYOK、数据不出境）。

**风险提示**：创始人公开了方法论文章，说明其认为壁垒在持续迭代的设计 know-how 与工程细节，而非单个 prompt。开源对标意味着我们也在明牌竞争——护城河只能是"可验证的交付质量"而非秘密。

## 九、SANDUN 四例任务回放解剖（2026-09-24，本项目实测抓取）

通过无头浏览器抓取了四份公开任务回放：北京五日游攻略（14 页）、正泰电器企业介绍、Dify 产品路演（12 页）、小米集团 2025Q3 业绩报告（23 页）。

**流水线实态**：会话式需求调研（生成 5 组维度的调研关键词→请用户确认/修改）→ 大纲（封面/目录/章节页/内容页/结束页结构）→ **逐页资料核查**：搜索型任务每页显示搜索词与"置信度"（如"北京核心景点 官方预约平台 汇总 放票规律"）；材料型任务（小米财报）显示每页引用的"参考资料"条数 → 内容策划（每页 4 个内容块规划 + 图片/图表计数百分比）→ 初稿 → 设计稿。播放器带全局视图、焦距编辑与快捷键。

**视觉取证**：抽取设计稿 SVG（viewBox 1280×720）填充色，三份成稿的主色族均为 Tailwind slate 灰阶 + `#2563EB` 蓝 + `#F8FAFC/#EFF6FF` 浅底——与 AGENTS参考资料 的默认色族同源。**三个题材（旅游/科技路演/财报）视觉风格同一化**，证实其风格库默认态是单一审美。

**可借鉴（加入我们产品）**：
- 逐页"搜索词+置信度"或"参考资料条数"的事实来源可视化——正是我们 R02 事实保真的交互形态样板；
- 初稿（结构）→ 设计稿（样式）两段式生成，便于早期早停与成本控制；
- 内容策划页的块级规划与资产计数。

**可攻击（我们的差异化）**：
- 视觉单一化（三个题材同色系）→ 我们走风格包多样化 + 品牌 VI 适配；
- SVG 输出（设计稿即 SVG）→ 我们走原生语义对象（图表嵌入工作簿、表格可增行）。

## 十、竞品交互模式横切（2026-09-24，第四轮；目的：去 SANDUN 中心化）

| 产品 | 生成入口 | 澄清 | 大纲门 | 修改交互 | 证据级别 |
| --- | --- | --- | --- | --- | --- |
| Gamma | Generate（prompt/粘贴/导入）+ Agent 模式 | Agent 模式问少量“smart questions” | 大纲可编辑后生成 | 卡片式编辑 + AI 编辑（**带预览与回滚**）+ 导出 | 官方帮助中心 |
| Gemini in Google Slides | 侧栏对话 | 官方主打“quick, tailored conversation to refine the details” | 大纲生成后可调 | **宿主原生编辑**（Slides 本身就是编辑器）；可引用 Drive 文件、可匹配另一份稿的风格 | 官方文档/官方博客 2026-06 |
| Plus AI（PPT/Slides 插件） | prompt / 上传文件 / 模板 | 弱化 | 大纲可自定义后生成 | **宿主原生编辑** + Rewrite（改写）与 Remix（重排）分开 | 官方指南 |
| Kimi K3 | 对话（可附文件/模板/图片） | 轻 | 有 | 自有在线编辑器 + 批注 + 多轮对话 | 官方指南 |
| SANDUN | 对话 + 项目制 | 调研关键词请用户确认 | 便利贴拖拽 | 画布编辑 + 对话 | 本项目实测回放 |

**横切结论**：

1. **“澄清→大纲确认→生成”是三产品以上共识**（Gemini/Gamma/Plus/SANDUN），不是 SANDUN 特有，放心采用；
2. 修改交互存在两大路线：**宿主原生编辑**（Gemini/Plus/ChatGPT for PowerPoint——插件路线零编辑器投入，用户留在 PowerPoint 里）vs **自有编辑器**（Kimi/SANDUN/Gamma——重投入）。我们已否掉自有画布编辑器；对话式修改 + 结构化面板是介于其间的第三态，成本可控；
3. Gamma 的“AI 编辑带预览+回滚”是低成本高信任的修改交互，直接借鉴（与我们版本/回退需求 R08 同构）；
4. Gemini 的“匹配另一份稿的风格”提示风格包可以从既有 PPTX 提取——风格库输入的极简形态，记入待议。

## 十一、四道门模型的 HITL 尽调（2026-09-24，第五轮）

所有者要求对四道门做“是否最优解”的尽职调查。证据与结论：

**HITL 文献共识（5 个独立从业者来源）**：审批门只应设在错误代价高或不可逆处；对可逆步骤设卡会造成确认疲劳、橡皮图章化，反而降低安全性。全自动路线（Manus/Genspark）确实存在且以“无摩擦”为卖点。

**逐门核查**：
- 澄清门（受众/场景错→全稿报废，爆炸半径大）→ 保留，但提问上限 3 个、可跳过、默认值可见；
- 大纲门（此处改=零成本，过后改=全量重生成）→ 保留，四方竞品共识；
- 代表页门（方向错=全量重生成，成本高但可逆）→ **保留但可跳过**，且必须显示成本预估才有意义；设遥测观察跳过率，普遍跳过则降级；
- 交付门（自动质量门，不占用户摩擦预算）→ 保留，人工不可降级绕过。
- 全自动无门（Manus 式）→ 被否：滩头是正式汇报，“当众出错”的代价高于等待 30 秒；保留跳过逃生阀以防摩擦驱赶用户。

**结论**：四道门经受住尽调，附加校准事项已写入 ADR-0008。

## 十二、需求面公开证据（2026-09-24，第六轮；所有者指示：不做访谈，以公开资料取证）

### 12.1 付费意愿的硬代理：PPT 代做市场

- 天猫 PPT 制作类目**月交易额 4500 万元+（年 5.4 亿口径）**（B 站从业者引天猫后台大盘，中等证据）；
- 价格分层清晰：学生/简单单 10–30 元/页；商业路演 80–300 元/页；高端定制 500–2000 元/页（新浪财经、cbndata、mmaimai 等）报道与从业者自述）；
- 关键细节：**5–10 元/页的低价单“实为 AI 自动生成或学生兼职，修改率高达 80%”**——AI 低价货质量差已成为从业者共识，正佐证“质量兑现”空档（营销性质来源，中性采信）。

### 12.2 品类需求的巨头验证

- **WPS AI**：国内月活 **8013 万（同比 +307%）**，日均 token 调用超 2000 亿；金山办公 2025 营收 59.29 亿（+15.78%），累计付费个人用户 4615 万（+10.67%），官方称 AI 能力已成为付费转化的重要驱动，并探索“订阅+AI 用量”计费（2025 财报及多家财经媒体报道，强证据）。
- **Gamma**：CEO 官宣 $100M ARR、**7000 万用户**、持续盈利，$2.1B 估值（a16z 领投 $68M B 轮；TechCrunch 2025-11-10 报道，强证据——注意数字为公司自述）。
- 反例：**Tome 已停服**（第三方横评实测时发现）——赛道有需求不等于随便做都能活。

### 12.3 耗时与痛点调查

- empower 《The Ultimate Global PowerPoint Study》（2020，1102 名德美办公室员工，方法透明）：**最耗时环节是格式化**（创建/调整图表、找模板与图片图标），一手严谨调查，但非中国样本；
- 中文流传数字：“咨询公司员工每周 6.3 小时在 PPT 美化”“74.6% 视觉包装时间超过内容提炼”（头条文引述，**原始出处不可核**，只作氛围证据）；“68% 职场人每周 5 小时+做 PPT”（营销性质来源，低级别）。

### 12.4 市场规模（方向性弱证据）

AI 演示生成市场：TBRC 估 $1.94B(2025)→$6B(2030) @25.3% CAGR；Valuates 估 $643M→$1.32B @11%；HNY 估 $542M→$1.11B @12.8%。**同一市场估值分歧达 3–4 倍**，全部只作“多家机构认为高增长”的方向性证据，不用于任何测算。

### 12.5 结论（已回填 02 报告 v2 第二节）

- **品类需求不需要我们再证明**：代做市场付费分层、WPS AI 增长、Gamma 商业成功三条独立证据链成立；
- 开源非商业定位下，“付费意愿”改写为“采用意愿”：待验证的是**差异化是否构成迁移理由**（A 级语义/中文零溢出/事实保真/自托管），验证手段=同题测试对比 + 开源发布后的采用指标（部署数/star/社区反馈），而非访谈付费；
- 访谈/问卷路线按所有者指示关闭。

## 十三、SANDUN 交互设计模式的定位判断（2026-09-24，回应所有者提问）

**问题**：SANDUN 的设计交互模式与其他热门产品相比如何？我们项目怎么定位？

**SANDUN 模式的优点（值得学）**：过程全透明（流水线回放可见）；阶段产物分离（大纲/策划稿/初稿/设计稿）；逐页来源可视化（搜索词+置信度，材料型任务显示参考资料条数）；项目制+风格库+模型分档（旗舰/专家）。

**SANDUN 模式的缺陷（我们避开）**：输出 SVG 化导致 B 级可编辑；视觉单一族（实测三题材同色系）；画布编辑器重交互学习成本高；积分墙+邀请裂变的增长机制；“置信度”是一个黑盒数字而非可核验证据链。

**与热门产品的交互谱系对比**：
- 比 Gamma 重：Gamma 更轻快（40 秒出稿），但中文弱、事实无保障；
- 比 Kimi K3 收敛：Kimi 是“大而全编辑器”，SANDUN 是“流水线+画布”，两者都是托管黑盒；
- 比 Manus/Genspark 可控：全自动省心但正式场合不敢用；
- 比 Gemini/Plus 独立：插件路线零摩擦但被宿主生态锁死。

**我们的定位（一句话）**：交互姿态取 SANDUN 的“透明流水线”与 Gamma 的“轻量回滚”，抛弃画布与积分墙；交付标准用别人都没有的“可核验审计报告”收束——**做一个敢让你直接拿去汇报的工具**，过程每一步可见、可审、可回滚，结尾给出证据而不是自信。

## 十四、技术路线重估：ADR-0003 被证伪的部分与 .NET 提案（2026-09-24，所有者发起）

所有者对 03 报告 v2 / ADR-0003 明确表示“一点都不满意”。重新以五年维护视角审视，TS 全栈的三个硬伤：

1. **选型忠诚对象错误**：按生态时髦度（agent 圈流行 TS）而非按项目核心资产（OOXML 文档引擎：生成/审计/受控补丁/保真）选栈；
2. **PptxGenJS 的能力边界与护城河科目正交**：它能“写”，不能“读”——读、补丁、审计、校验恰是本项目差异化所在；
3. **Rust 客户端的远期版图未被纳入**（所有者明示客户端推迟但必做、未来为 Rust）——纯 TS 栈意味着引擎将来整体重写。

Spike C 同题实测（记录见 research/experiments/）：.NET 8 + Open XML SDK 在同题下完成 TS 路线做不到的事——C1 受控补丁（改图表缓存+嵌入工作簿，余部不动，WPS 复检持久）；C2 SkiaSharp 量字与 fontkit 完全一致；C3 模板克隆增页成立、从零建包需自建脚手架。

**提案（ADR-0009，待确认）**：文档引擎/后端 = .NET + Open XML SDK（微软官方、MIT、全 schema 强类型、自带校验）；量字 = SkiaSharp；前端 = Next.js（纯 UI 层）；Rust 客户端 = 未来 Tauri 壳，复用同一 Web UI 与服务端 API，引擎不需重写。代价：SDK 生成端需自建包装层（恰好成为自有资产）、C# 贡献者生态小于 TS、镜像体积略增。SANDUN 的对标研究、四道门交互、风格包体系、审计报告与量字方法论**均不受语言切换影响**。
