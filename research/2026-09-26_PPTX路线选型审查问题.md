# PPTX 路线选型审查问题（研究阶段）

- 日期：2026-09-26
- 性质：研究审查清单，不是实现任务，不是技术决策
- 目的：在任何候选被宣布为“最优”前，强制回答版本、宿主、产物和 SANDUN 产品层吸收问题

## 1. 唯一目标

> 哪条整体路线最适合交付高质量、原生可编辑、可审计的 PPTX？

不得用语言偏好、熟悉度、星数、既有实现投入、用户曾提过的候选名称或单项 API 漂亮度替代这个目标。

## 2. SANDUN 吸收边界审查

候选方案必须回答：

| SANDUN 机制 | 应吸收到产品哪里 | 不得吸收什么 |
| --- | --- | --- |
| 分阶段生成 | 任务状态/阶段门/用户确认 | 不复制 SANDUN 的接口字段和视觉细节 |
| `awaiting_confirm` | 人工确认与暂停恢复 | 不允许无边界自动推进 |
| 搜索计划和研究阶段 | 材料研究与来源审计 | 不把搜索结果直接当事实 |
| 初稿 → 风格 → 正式设计 | 内容、设计、产物三层分离 | 不让视觉设计覆盖事实来源 |
| 页面级重排 | 单页重新生成/版本比较 | 不影响其他页的对象和来源链 |
| `chart_plan` | 原生图表的数据契约 | 不止生成 SVG 或形状拼图 |
| 设计令牌 | 风格包/母版/版式/图表皮肤 | 不把 CSS 字体名写入 PPTX |
| 导出阶段进度 | 产物组装与验收进度 | 不把“导出完成”当作 WPS/PowerPoint 验收完成 |

## 3. 版本稳定性审查

每个候选必须给出：

- 精确生产引擎版本；
- 精确消费软件版本；
- 模板、母版、版式和字体版本；
- API/SDK requirement set 或运行时版本；
- 支持范围和不支持范围；
- 同一输入的保存重开契约；
- 升级、回滚和重新生成策略。

### 3.1 可接受版本差异

- 差异被支持矩阵明确覆盖；
- 产物 hash、部件清单和目标软件行为可重现；
- 不支持的对象显式阻断或降级；
- 升级可以回归、回滚，不改变历史交付的解释。

### 3.2 必须淘汰/隔离的版本差异

- 静默图片化；
- 丢失图表工作簿或未知部件；
- 关系闭包变化且无法解释；
- 中文行高、字体替换或断行随版本漂移；
- 同一支持范围内无法重现结果；
- 供应商没有明确版本范围和升级支持边界。

## 4. 产物能力审查

以下问题必须逐项得到“官方明确 / 本项目实测 / 未知”，不能用“支持 PPTX”笼统回答：

1. 原生图表部件是否存在？
2. 图表是否真正关联嵌入工作簿？
3. 改工作簿后缓存是否同步？
4. 表格是否是原生 `<a:tbl>`？
5. 备注页是否存在且内容正确？
6. 母版、版式和主题继承是否保留？
7. 未知部件和未知关系是否保留？
8. 真文本和中文字体策略是否稳定？
9. WPS/PowerPoint 是否都能打开、编辑、保存、重开？
10. 产物是否能输出对象清单和来源审计？

## 5. 当前候选的研究状态

| 候选/策略 | 当前状态 | 下一项必须补的证据 |
| --- | --- | --- |
| PowerPoint 原生自动化 | PowerPoint 宿主保真候选 | Office 版本矩阵、无人值守边界、WPS 交叉行为 |
| Aspose.Slides | 独立服务强候选 | 真实图表 workbook、未知部件、WPS 保存重开、版本升级边界 |
| Syncfusion Presentation | 独立服务候选 | 原生图表与 workbook 关系、未知部件、版本与许可证资格 |
| GemBox.Presentation | 独立服务候选 | preservation 对本项目夹具的适用性、图表 workbook、版本策略 |
| 模板优先 + 包级编辑 | 跨引擎产物策略 | 未修改部件保留、关系闭包和自由结构生成边界 |
| WPS 原生自动化 | 部分对象能力已证实、核心产物语义待证的条件性候选 | 只有在业务明确要求 WPS 作为作者或主验收宿主时，才继续补 embedded workbook、备注写入、未知关系和版本契约 |
| SANDUN | 产品流程参考，不是产物引擎 | 不再扩大吸收范围；保持规划层吸收、导出层拒绝 |

## 6. 禁止提前写代码的触发条件

以下任一条件成立时，继续研究，不写验证代码：

- 候选矩阵仍缺版本和许可信息；
- 同一术语“原生图表”未拆成部件、工作簿、缓存、可编辑行为；
- SANDUN 的产品层参考和导出层拒绝没有分别记录；
- 还在用用户之前提到的候选名称作为完整候选池；
- 还没有明确本候选最可能失败的对象和版本组合；
- 还没有决定验证对象级事实与视觉事实如何分开记录。

## 7. 当前结论

目前只能说：

> 产品体验应参考 SANDUN；最终产物必须是原生 PPTX；PowerPoint 原生和商业 SDK 是主要路线候选；模板优先是跨路线策略；版本稳定性和对象级产物证据完成前，不宣布唯一技术。

本文件不授权实现，不授权 benchmark，不授权选择某个 SDK。

## 8. 吸收分类（研究阶段）

| 对象/机制 | 吸收分类 | 当前边界 |
| --- | --- | --- |
| SANDUN 阶段式生成、确认节点、页面级重排 | **适合二开** | 只吸收产品流程和状态思想，不复制视觉、接口或导出实现 |
| SANDUN `chart_plan` 结构化字段 | **可直接复用** | 可作为图表规划/审计契约；必须在最终产物中还原为原生语义 |
| SANDUN SVG/形状展平导出 | **应当淘汰** | 与原生图表、嵌入工作簿和原生表格目标冲突 |
| SANDUN `system-ui` 字体策略 | **应当淘汰** | 不能作为跨宿主中文字体方案 |
| PowerPoint 原生对象模型 | **仅可借鉴** | 目前是重要候选，但版本、无人值守和 WPS 交叉行为未完成审查 |
| Aspose.Slides / Syncfusion / GemBox | **仅可借鉴** | 目前是独立服务候选，不能把官方功能列表写成项目通过 |
| 模板优先 | **可直接复用** | 作为跨路线产物策略，但模板与包级关系保留仍需验证 |
| Open XML 包级局部编辑 | **适合二开** | 用于局部缺口、关系保护和审计，不自动承担整稿生成 |
| HTML/SVG 作为最终导出 | **应当淘汰** | 不能证明 A 级原生语义 |
| 未具备对象级能力和版本矩阵的候选 | **应当淘汰** | 不能用“支持 PPTX”笼统声明进入主候选 |
