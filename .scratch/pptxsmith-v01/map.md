# Wayfinder：PptxSmith v0.1 工程启动规格

## Destination

定稿一份可以交给后续工程会话执行的 **PptxSmith v0.1 工程启动规格**：影响首期产品价值、技术路线、用户体验、质量验收和开源维护的决定全部有答案、有证据、有取舍；没有关键未知会迫使工程过程中临时改方向。

## Notes

- 领域：中文商务 AI PPTX，首期为公司内部工作汇报、培训、展示；听众是领导与同事。
- 当前阶段：只做研究、决策和必要的最小验证；不在本地图内直接建设 v0.1。
- 工作方式：按模块逐个清；每张票只解决一个决定/调查；解决票后再推进下一张。
- 必读：`VISION.md`、`CONTEXT.md`、`docs/企业级工程流程与项目治理.md`、`research/2026-09-24_仓库全量审查.md`、四份 v2 报告、相关 `docs/adr/`。
- 当前阶段门：先冻结架构决策驱动和质量属性，再按前端、后端、文档引擎、任务/模型、数据文件、解析/渲染、安全供应链、测试/可观测/发布逐模块调查，最后做总架构决策。
- 原则：证据分级（官方声称/第三方实测/本项目实测）；技术优先复用成熟方案，必要时二开；只有没有合适基础时才自建。
- 技术终决纪律：先围绕核心目标定义淘汰条件，再做候选比较；在同一兼容性语料库和 PowerPoint/WPS 交付门通过前，不接受任何语言或库为最终答案。
- 质量底线：长期维护、企业级标准；研究性原型不能直接进入主线；不以“能跑”替代“好用、爱用、解决 PPTX 痛点”。
- 决策票类型：`grilling` 需要所有者判断；`research` 由联网/源码调查解决事实；`prototype` 用具体低保真产物帮助决策；`task` 只做阻塞决策的准备工作。

## Decisions so far

- [中文字体与校准矩阵方案](issues/04-中文字体与校准矩阵方案.md)：固定静态 Source Han Sans/Noto CJK 基线，统一使用 HarfBuzz-backed shaping，按字体×目标软件二维校准；商用字体上传必须单独处理授权。
- [校验与渲染 QA 工具盘点](issues/03-校验与渲染QA工具盘点.md)：交付闸门必须组合 OpenXmlValidator、关系/部件闭包、语义探针、HarfBuzz-backed 字体/几何检查、LibreOffice 独立渲染信号和 PowerPoint/WPS 目标软件抽检；任何单项都不能代表最终真相。

## Not yet specified

- 受控补丁何时重启、首个支持对象边界与旧稿保护承诺；
- 从既有 PPTX 提取风格包的输入协议和授权边界；
- 风格包 v1 以外的场景包（党政、咨询、学术、培训等）及发布标准；
- WPS 与 Microsoft PowerPoint 的双目标验收矩阵细节；
- 模型成本预算、并发、任务取消与失败重试的产品策略；
- Rust 客户端的离线能力、同步协议与何时启动；
- 社区治理、版本支持周期、贡献者晋升和安全响应细则。

## Out of scope

- v0.1 的移动端与原生 Windows/macOS 客户端；
- v0.1 的商业 SaaS、积分、订阅、邀请裂变；
- v0.1 的自由画布编辑器；
- v0.1 的已有 PPTX 受控补丁入口；
- 任何未经同题测试和交付闸门验证的“全格式/全对象/全平台”承诺。
