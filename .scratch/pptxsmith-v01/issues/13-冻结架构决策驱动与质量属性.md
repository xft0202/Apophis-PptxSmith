# 冻结架构决策驱动与质量属性

Type: grilling
Status: open

## Question

在继续比较前端、后端、文档引擎和基础设施前，冻结本项目的架构决策驱动（Architecture Decision Drivers）与质量属性场景，避免用通用技术偏好替代项目目标。

必须明确并排序：

- 用户交付：PPTX 在 PowerPoint/WPS 打开、编辑、保存、直接汇报的成功标准；
- PPTX 保真：新稿原生语义、未来受控补丁、未知部件/关系/备注/嵌入对象保留边界；
- 中文质量：字体、shaping、折行、行高、溢出和目标软件差异的容差；
- 产品体验：四道阶段门、等待、回滚、来源、成本、失败和降级的可理解性；
- 开源维护：MIT 依赖、成熟度、贡献者进入、上游替换、版本支持和五年维护风险；
- 部署与平台：Linux Docker、多用户、模型可配置、PC Web ≥1440px、未来 Rust 客户端 API；
- 可靠性与安全：文件隔离、模型密钥、任务幂等、恢复、审计、升级和供应链；
- 工程约束：哪些能力必须复用/二开，哪些缺口允许自建，哪些方案直接淘汰。

输出必须形成可评分的质量属性场景和候选淘汰条件。没有这张票的结果，后续前端/后端/文档引擎技术选型都不得定稿。
