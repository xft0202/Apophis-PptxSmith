# 冻结架构决策驱动与质量属性

Type: grilling
Status: resolved

## Question

在继续比较前端、后端、文档引擎和基础设施前，冻结本项目的架构决策驱动（Architecture Decision Drivers）与质量属性场景，避免用通用技术偏好替代项目目标。

## 强制比较原则

本票以及后续所有模块票必须贯彻 **博采众长，取其精华，去其糟粕**：

- 每个方面至少比较多个成熟项目或官方方案，不能只围绕一个熟悉语言或库收集支持材料；
- 对每个候选分别标注：可直接复用、适合二开、仅可借鉴、必须隔离、应当淘汰；
- 比较必须覆盖用户任务、质量属性、许可证、维护活跃度、部署复杂度、供应链和验证成本；
- 任何从外部项目吸收的能力，必须写明边界、版本策略、替换路径和新增测试夹具；
- “取其精华”不等于拼装最多组件；若组合造成验证矩阵、升级风险或运维负担超过产品价值，应淘汰该组合。


- 用户交付：PPTX 在 PowerPoint/WPS 打开、编辑、保存、直接汇报的成功标准；
- PPTX 保真：新稿原生语义、未来受控补丁、未知部件/关系/备注/嵌入对象保留边界；
- 中文质量：字体、shaping、折行、行高、溢出和目标软件差异的容差；
- 产品体验：四道阶段门、等待、回滚、来源、成本、失败和降级的可理解性；
- 开源维护：MIT 依赖、成熟度、贡献者进入、上游替换、版本支持和五年维护风险；
- 部署与平台：Linux Docker、多用户、模型可配置、PC Web ≥1440px、未来 Rust 客户端 API；
- 可靠性与安全：文件隔离、模型密钥、任务幂等、恢复、审计、升级和供应链；
- 工程约束：哪些能力必须复用/二开，哪些缺口允许自建，哪些方案直接淘汰。

输出必须形成可评分的质量属性场景和候选淘汰条件。没有这张票的结果，后续前端/后端/文档引擎技术选型都不得定稿。

## Reopened

本票原有答案已撤回部分结论。质量属性排序和硬门仍保留，但“最小自托管优先”曾被解释为减少生产基础设施，导致错误的 SQLite/本地文件过渡思路。现在改为：长期生产基础能力必须第一天到位；部署体验可以简单，生产语义、数据、备份、安全和替换边界不能临时化。

### 1. 决策结论与适用范围

本票冻结的是 **架构决策驱动和评审方法**，不是冻结某一种语言、框架或 PPTX 引擎。任何后续候选都必须先通过硬门，再按同一组质量属性评分；没有同题测试集、许可证核验和目标软件证据的候选，只能停留在研究隔离区。

决策优先级如下：

1. **用户能否敢于交付和汇报**：PPTX 在 Microsoft PowerPoint 与 WPS 中打开、编辑、保存、重开和直接展示；
2. **PPTX 语义与范围保真**：原生对象、嵌入工作簿、关系闭包、未来受控补丁和未知对象保护；
3. **中文排版与事实保真**：不缺字、不溢出、不静默改数字或结论，来源和审计可追溯；
4. **可控产品体验**：四道阶段门、进度、成本、来源、取消、失败、降级、版本和回滚可理解；
5. **长期维护与开源贡献**：MIT 主线、许可证清晰、上游可替换、贡献者可接手、五年风险可管理；
6. **部署和平台约束**：Linux Docker、一人部署多人使用、BYOK、PC Web `>=1440px`、未来 Rust 客户端可复用 API；
7. **安全与可靠性**：项目/成员隔离、密钥保护、不受信任文件处理、任务幂等、恢复、升级和供应链可审计；
8. **工程效率与演进能力**：测试、观测、发布、迁移和故障定位成本不能压垮长期维护。

### 2. 可评分的质量属性场景

评分采用 0–5 分，先检查硬门，再按权重计算。某一硬门失败时总分无效；通过硬门后总分低于 3.5/5，或任一 P0/P1 场景低于 3/5，不得进入主线。权重合计 100。

| 优先级 | 属性 | 权重 | 场景（来源 / 刺激 / 环境 / 制品 / 响应 / 度量） |
| --- | --- | ---: | --- |
| P0 | 用户交付成功 | 20 | 来源：同题测试集；刺激：用户提交中文汇报材料并完成四道门；环境：Linux Docker 生成，PowerPoint/WPS 目标版本打开；制品：PPTX、审计报告、版本记录；响应：文件可打开、可编辑、可保存并重开，目标对象的编辑探针通过；度量：承诺对象 100% 通过，测试样本 0 个阻断级打开/重开错误。 |
| P0 | PPTX 语义与包保真 | 20 | 来源：新稿和未来受控补丁兼容性语料库；刺激：生成或仅授权修改文字、表格、图表；环境：含 master/layout/theme、chart、embedded workbook、notes、外链和未知部件的 PPTX；制品：原始 OPC 包、输出包、部件闭包报告；响应：只写授权部件，图表缓存与工作簿同步，未授权部件不静默丢失；度量：目标对象 A/B 等级达到该样本承诺，关系/部件闭包 100% 通过，未来补丁路径的未授权变更为 0。 |
| P0 | 中文排版 | 15 | 来源：固定字体与中文混排 fixture；刺激：中文、英文、数字、标点、长标题、缺字和极端数据组合；环境：固定字体版本、Linux 量字、PowerPoint/WPS 分开验收；制品：布局几何报告和截图；响应：按 shaped glyph/cluster 折行，发现不确定就阻断交付；度量：承诺样本 0 个缺字、0 个溢出、0 个越界，字体×目标软件校准误差记录在明确容差内，不宣称像素一致。 |
| P0 | 事实保真与审计 | 12 | 来源：用户原文、表格和可选外部检索；刺激：模型尝试总结、改写、补充数字或引用外部事实；环境：默认不联网，联网必须显式开启；制品：语义对象模型、来源引用、模型调用记录、审计报告；响应：原文数据和结论零静默改写，外部事实带来源，冲突进入用户确认；度量：数字/单位/结论差异为 0 个未标记变更，每个对外事实有可回溯来源或明确缺源。 |
| P1 | 阶段门与可控体验 | 10 | 来源：四道门任务脚本；刺激：用户修改大纲、拒绝代表页、取消任务、重试失败步骤、回滚版本；环境：长任务、模型超时、provider 不支持结构化输出；制品：事件流、阶段状态、版本和错误信息；响应：状态可解释、可取消、可恢复、可回滚，禁止“后台仍在跑但 UI 无状态”；度量：每个长任务有可重放事件，首个进度事件目标 <2 秒，交互请求 p95 <500ms，失败必须给出下一步或安全降级。 |
| P1 | 安全与可靠性 | 10 | 来源：多成员部署和不受信任文件；刺激：跨项目访问、恶意 ZIP/PPTX、宏/OLE/外链、提示注入、泄露 provider 密钥、重复提交；环境：单节点 Docker，管理员和成员并发操作；制品：权限判定、隔离目录、密钥存储、审计日志、备份；响应：拒绝越权和危险对象，任务幂等，密钥不进入日志，恢复后版本和审计一致；度量：越权测试 0 次成功，密钥泄露 0 次，重复提交不产生重复交付，备份恢复演练通过。 |
| P1 | 长期维护与开源 | 8 | 来源：候选源码、发布记录、许可证和依赖树；刺激：上游 breaking change、维护者退出、贡献者提交适配、漏洞升级；环境：五年维护假设，MIT 主线；制品：适配层、锁文件、SBOM、升级/替换方案；响应：上游变化局部化，核心语义模型不被供应商 API 绑死；度量：关键候选有明确版本策略和替换路径，主线依赖许可证可审计，单一作者/归档/不透明许可证只能作为风险项或隔离项。 |
| P2 | 部署、性能与演进 | 5 | 来源：最低配置和代表性负载；刺激：多用户同时上传、解析、生成、预览；环境：Linux Docker 单节点，未来可拆分 worker；制品：Compose、迁移脚本、健康检查、指标；响应：资源受限时排队、限流、降级，不因单个任务拖垮 Web/API；度量：目标负载下无 OOM/数据损坏，长任务与交互请求资源隔离，最小安装不强制云服务或 GPU。 |

权重解释：交付、PPTX、中文和事实四项合计 67%，因为它们直接构成首期铁三角和“敢不敢上会”的判断；体验、安全、维护是进入长期主线的必要条件；性能不能用来补偿语义、排版或安全失败。

### 3. 候选评审的统一输出字段

每个模块、项目或库都必须按以下字段记录，缺一项不得写成“推荐”：

| 字段 | 要求 |
| --- | --- |
| 用户任务 | 它解决四道门中的哪个真实任务，不能只写“支持 AI/高性能”。 |
| 官方声明 | README、官方文档、许可证原文；标注为“官方声称”，不等于本项目已验证。 |
| 源码证据 | 关键入口、数据结构、测试、部署文件和依赖边界。 |
| 本项目实测 | 夹具、版本、字体、目标软件、输入输出和失败记录。 |
| 许可证与供应链 | 主许可证、例外目录、模型/字体/第三方依赖、SBOM 和升级风险。 |
| 维护信号 | 最近发布、提交活跃度、贡献者分布、issue/PR 响应、是否归档、是否单一作者。 |
| 组合成本 | 新增服务、数据库、网络、镜像、运行时、测试矩阵和升级面。 |
| 吸收分类 | 只能选择：**可直接复用 / 适合二开 / 仅可借鉴 / 必须隔离 / 应当淘汰**。 |
| 替换路径 | 上游停更、许可证变化、性能不足或兼容性失败时如何替换。 |
| 新增夹具 | 引入后必须新增哪些语料、权限、故障、升级和目标软件测试。 |

### 4. 当前证据对候选的初步约束

以下不是最终技术定案，而是供后续模块票使用的边界：

- `DocumentFormat.OpenXml` 的官方 API 覆盖 Open XML 包、部件、关系和 `OpenXmlValidator`，适合作为低层事实源和包级 QA 基础；它不自动证明 PowerPoint/WPS 视觉和交互等价。
- `ShapeCrawler` 的官方文档提供较高层的形状、表格、图表、SmartArt 等操作接口，适合评估为 .NET 加速层；未知部件、关系闭包和跨生成器保留仍需同一语料库验证，未验证前不能作为唯一事实源。
- `PptxGenJS` 的官方文档和本项目 Spike A 证明其新稿原生图表/表格路线有价值；但它是生成器，不应自动承担未来受控补丁、未知部件保留和整包 round-trip 的唯一职责。
- `gopptx` 的许可证和功能声明值得调查，但本项目已发现它修改 PptxGenJS 产物时出现 chart part 路径兼容失败；在跨生成器、嵌入工作簿、notes/comments/custom XML 和未知关系测试通过前，只能是实验候选。
- Presenton、PPT Master、PPTist、Dify、Open WebUI、LibreChat、Flowise 等项目分别提供 AI 演示流程、原生 PPTX 生成、结构化编辑器、模型/工作流、自托管和多 provider 的可借鉴证据；它们的许可证、归档状态、服务复杂度和产品边界不同，不能整体复制。
- Context7 官方库资料适合核对 API 能力和生态入口，不能替代 GitHub 源码、许可证审查或本项目实测。尤其是“OpenAI-compatible”只证明请求形状，不证明结构化输出、工具调用、图像接口或错误模型语义等价。

### 5. 硬淘汰条件

满足任一条件，候选不得进入主线核心；若有局部价值，只能以隔离服务、研究样例或设计参考存在：

1. 生成承诺对象被静默图片化，或图表/表格无法完成目标软件中的编辑探针；
2. 未通过 PowerPoint/WPS 打开、保存、重开，或无法解释失败对象和降级范围；
3. 在同题语料库中丢失未知部件、关系、备注、嵌入工作簿或未授权对象，且没有包级保护策略；
4. 中文缺字、溢出、换行或字体替换没有可测量的阻断/降级机制；
5. 许可证与 MIT 主线、再分发、网络服务或品牌使用边界冲突，且无法通过清晰的进程隔离和 NOTICE 解决；
6. 只能依赖商业 SaaS、必须把敏感材料发送到不可控服务，或没有 BYOK/本地 provider 路径；
7. 长任务没有幂等、取消、超时、重试、恢复和人工确认边界；
8. 不能进行项目/成员级访问控制，或密钥、文件和审计记录会跨边界暴露；
9. 维护状态已经归档、关键能力由单一不可替代个人维持、版本策略不透明，且没有替换计划；
10. 引入它所增加的服务、许可证、目标软件、性能和升级矩阵超过其对首期用户任务的可验证价值。

### 6. 最小验证门

后续每个模块票至少提供以下材料，才能提出架构候选：

- 一张 3–6 个候选的对比矩阵，含上表全部字段；
- 一份官方文档/源码/许可证引用清单；
- 一个最小可复现实验，写明输入、版本、运行环境和失败边界；
- 一个组合后的部署、测试和替换影响说明；
- 明确哪些能力吸收、哪些拒绝，不能只写“综合考虑”；
- 对 P0/P1 场景的预期得分和未决风险；
- 若候选触及 PPTX，则必须接入统一兼容性语料库和 PowerPoint/WPS 抽检计划。

### 7. 暂定架构约束

在总架构决策前，以下约束视为冻结：

- **原始 OPC 包是 PPTX 事实源**；语义对象模型是生成和审计的中间契约，不得反过来成为未经授权的整稿重建借口；
- **文档引擎与应用运行时解耦**；后端语言不因文档引擎语言而被强行锁定，使用稳定的进程/API/队列边界；
- **模型 provider 与业务流程解耦**；LLM、嵌入、生图、检索和渲染必须有能力声明、超时、错误、成本和数据路由边界；
- **预览不是交付真相**；浏览器/LibreOffice/其他转换器可提供预览和独立信号，最终中文排版和编辑性以目标软件验收为准；
- **核心主线优先 MIT 兼容**；非 MIT、未知或有多租户/品牌/网络服务附加限制的项目不得未经法务与隔离评审进入核心依赖；
- **长期生产基础优先**；单节点 Linux Docker 是部署形态，不是降低数据库、对象存储、备份、身份、任务恢复或安全等级的理由。生产部署从第一天使用经评审的长期数据/文件/权限基础；可以通过 Compose profile、安装向导和默认配置降低使用复杂度，但不得引入计划迁移的临时实现；

- **显式降级优于静默失败**；不支持的对象、provider 能力和字体必须显示范围、风险和替代路径，并写入审计报告；
- **研究代码不得进入生产主线**；未通过同题测试和交付闸门的实验只能留在 `research/experiments/`。

### 8. 未决但不阻塞本票的参数

以下数值和版本在模块票/夹具中校准，不改变本票的优先级与硬门：

- PowerPoint/WPS 的具体版本和视觉 diff 容差；
- 首期承诺的对象类型清单及每类 A/B/C/D 比例；
- 单节点最低 CPU/RAM、并发任务数和生成时限；
- RPO/RTO 的最终部署档位；
- 结构化输出能力探测和 provider 兼容性分级；
- 受控补丁开放前的 12 份复杂样本及未知部件清单。

这些属于后续模块的验证参数，不允许在工程实现阶段临时改变质量属性排序。
